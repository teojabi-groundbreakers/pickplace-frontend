# 파일 준비 없는 행정동 경계 조회

확인일: 2026-10-20 (Asia/Seoul). [이슈 #10](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/10)의 온라인 대안 조사입니다. 공식 명세·현재 FE 코드·인증 없는 HTTP 진단 1회를 확인했으며, 실제 인증·경계 수신·운영 연결은 완료하지 않았습니다.

## 결론과 후보 비교

**SGIS 경계 연계는 사용자 최신 요청에 따라 필수가 아닌 후순위 검토사항으로 보류합니다.** [SGIS.md](SGIS.md)에 공식 명세와 재개 시 검토 항목을 남깁니다. 도입 확정·즉시 구현·키 준비나 현재 배포의 선행 조건이 아닙니다. 재개한다면 통합된 메인 API 서버에서 처리하고 카카오맵에 표시하는 방향입니다. 인증·지역 대응·좌표계·기준일·사용 조건과 실제 연결은 미검증입니다.

| 후보                               | 확인한 내용                                                                                                                    | 판단                                                                                                 |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| SGIS Data API + 메인 BE            | 토큰 인증과 행정구역 경계 GeoJSON endpoint가 공식 명세에 있음. 메인 API 내부 연계 검토안                                       | 후순위 검토·구현 보류. 키/사용 조건·코드/CRS/기준일·실제 연동은 미검증                               |
| FE에서 SGIS 직접 조회              | JS 제공 인증 경로가 있으나 토큰 반환 API와 다름. 지도 SDK 문서에는 종료 예정 안내가 남아 있음. 현행 인증·CORS·지원 여부 미검증 | 현재 운영안으로 채택하지 않음. Secret을 FE에 넣지 않으며 공개 JS 예제만으로 가능하다고 확정하지 않음 |
| VWorld/공공데이터포털 법정구역정보 | 전국 WMS/WFS이지만 명시적으로 법정동 경계                                                                                      | 분석 단위인 행정동 H의 대체에서 제외                                                                 |
| 스마트서울맵 OpenAPI               | JSON/GeoJSON·주소/좌표·테마/콘텐츠 기능은 확인. 전국 행정동 경계 조회 계약은 확인하지 못함                                     | 이번 전국 H 경계 후보로 확정하지 않음                                                                |

후보 근거: [SGIS 경계 명세](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/addressBoundary.html), [SGIS 인증 명세](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/basics.html), [VWorld 법정구역정보](https://www.data.go.kr/data/15123903/openapi.do?recommendDataYn=Y), [스마트서울맵 공식 가이드](https://map.seoul.go.kr/smgis2/division/viewOpenApi). SGIS 외에 조건을 충족하는 공식 API가 없다고 단정하지 않으며, 이번 조사에서 전국 H 경계 온라인 조회를 확인한 후보는 SGIS입니다. 사설 GitHub/CDN 자료를 공식·최신 전국 경계로 대신 채택하지 않았습니다.

### VWorld 사용자 링크 검토

사용자 제공 [adsigg 명세](https://www.vworld.kr/dev/v4dv_2ddataguide2_s002.do?svcIde=adsigg)는 `LT_C_ADSIGG_INFO` **시군구** 경계입니다. `sig_cd` 예시는 `11650`이며 `GetFeature`·단일검색 `attrFilter`·GeoJSON·EPSG:4326·필수 API key와 등록 URL의 `domain`을 확인했습니다. 시군구 표시의 기술 후보이지만 H10 행정동 도형을 대신할 수 없습니다. 공식 원문은 HTTP 200으로 읽었고 실제 키/도형 조회는 수행하지 않았습니다.

별도 [ademd 명세](https://www.vworld.kr/dev/v4dv_2ddataguide2_s002.do?svcIde=ademd)의 예시는 `emd_cd=11650108`·서초동이며 코드 조회 팝업은 ‘읍면동(법정동)’으로 표시합니다. 명칭만 보고 H 행정동으로 채택하지 않습니다. [공식 행정구역도 목록](https://www.data.go.kr/data/15059008/openapi.do)도 시군구/읍면동 레이어를 구분합니다. 앞선 법정구역 자료 검토를 VWorld 전체에 H 자료가 없다는 주장으로 확대하지 않습니다.

VWorld의 별도 [센서스 행정동 자료](https://www.data.go.kr/data/15125055/fileData.do)는 SHP 파일이고 해당 등록 건의 공공누리 4유형 표시를 확인했습니다. 이는 온라인 H JSON API나 SGIS 직접 API의 이용 조건을 확인한 결과가 아닙니다. [2D데이터 API 정보](https://www.data.go.kr/data/15140372/openapi.do)는 무료·공공누리 1유형·운영 심의승인을 안내하며, [이용약관](https://www.vworld.kr/v4po_prcint_a001.do)과 [저작권정책](https://www.vworld.kr/v4po_prcint_a006.do)의 중계/캐시·영리 사용 조건은 개별 운영 조건 확인 대상으로 남겼습니다. 벡터 경계를 카카오에 표시하는 명시적 금지는 찾지 못했으나 운영 허용·실연결 성공으로 확정하지 않았습니다. SGIS를 포함한 경계 연계는 후순위 검토로 보류했으며 이 절은 비교 근거입니다.

## 권장 흐름과 현재 코드의 연결점

1. **FE → 중계 함수:** 우클릭의 원본 H10·지역명과 클릭 경위도를 전달하는 방안을 검토합니다. 현재 [경계 클라이언트](../src/lib/regionBoundary.ts)는 `GET /regions/{H10}/boundary`에 H10만 보내므로 좌표 방식에는 요청 계약 보완이 필요합니다. 아직 필드를 추가하거나 기존 [API 계약](API.md#get-regionsh10boundary)을 변경하지 않았습니다. 목록 선택의 대표 좌표를 사용할 때에도 실제 지역 대응을 확인해야 합니다.
2. **서버 인증:** `authentication.json`에 서비스 ID/Secret을 보내 토큰을 얻고 만료에 맞춰 재사용합니다. 키는 서버 환경에서 관리합니다. 기존 경로가 없는 현재 FE 저장소에 서버 인증을 추가한 상태는 아닙니다.
3. **지역 식별 → 경계 조회:** 클릭 경위도로 `rgeocodewgs84.json`의 행정동 요청(`addr_type=20`)을 보내 SGIS 코드 후보를 얻고 `hadmarea.geojson`에서 해당 코드·연도의 경계를 조회하는 흐름을 실증합니다. 공개 명세의 읍면동은 8자리이며 H10을 절삭해 만들지 않습니다. 역지오코딩 예제의 코드 조각도 실제 형식·기준일을 확인한 뒤 사용합니다. 같은 좌표라는 이유만으로 SGIS 통계 구역과 현재 카카오 행정동의 동일성을 확정하지 않습니다.
4. **검증·변환:** 경계의 실제 CRS를 확인해 WGS84 `[경도, 위도]`로 변환하고 모든 폴리곤/구멍·링·대표점을 검증합니다. SGIS에 [좌표 변환 API](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/coord.html)도 있지만 꼭짓점마다 호출하는 구조는 요청량/지연을 먼저 확인해야 합니다. 서버의 일괄 투영 변환도 후보입니다. 다운로드 SHP의 좌표계·기준일을 API 응답에 무조건 대입하지 않습니다.
5. **중계 함수 → FE:** 검증된 H10 대응, 출처·실제 기준일·대표점을 갖춘 기존 [RegionBoundary](../src/types/boundary.ts)로 반환하면 현재 Polygon/MultiPolygon·구멍·라벨 렌더러를 재사용할 수 있습니다. API가 연도만 제공하더라도 `boundaryDate`의 날짜를 임의로 만들지 않습니다. 대응 관계나 기준일이 확인되지 않으면 요청 H10으로 포장한 다른 경계를 반환하지 않습니다.
6. **캐시·장애:** 코드/경계연도/변환 버전이 섞이지 않도록 캐시하고 호출 제한·토큰 만료·상위 API의 오류 본문을 처리합니다. 서버리스의 캐시 지속성은 실행 환경에 맞춰 정합니다. 경계 장애는 기존처럼 분석/지도 장애와 분리하며 데모 도형으로 대체하지 않습니다. 캐시 저장 조건도 API 사용 조건에서 확인합니다.

위는 **설계 제안**입니다. 좌표 입력 계약·H10 대응 확인 방식·경계 기준일·기존 DTO 유지 여부는 FE/BE 담당자가 확정해야 합니다. SGIS가 제공하는 2025년 경계와 현재 카카오의 분동/통합 이후 행정동이 다를 수 있으며, 이름만 같거나 한 점이 포함됐다는 이유로 동일한 경계라고 판단하지 않습니다. 소지역 코드찾기 API의 오래된 예제도 최신 코드 규칙으로 복사하지 않습니다.

## 브라우저 단독 방식의 확인 범위

[SGIS 지도 SDK 시작 문서](https://sgis.mods.go.kr/developer/html/newOpenApi/api/mapApi/startMapAPI.html)는 지도 API·모바일 SDK의 2025-12-31 종료 예정 안내를 포함합니다. 현재 실제 종료 상태는 별도로 확인하지 않았으며 이 안내를 Data API 전체 종료로 확대하지 않습니다. `javascriptAuth.json`이 문서에 남아 있다는 이유만으로 현행 FE 경계 조회용 인증 수단이라고 간주하지 않습니다.

실제 키 없이 공식 경계 endpoint에 `year=2025`, 시도 코드 `11`, `low_search=0`, 개발 출처 Origin을 보낸 **무인증 GET 1회**는 HTTP 500·HTML 본문·`Access-Control-Allow-Origin` 헤더 없음으로 응답했습니다. 이는 인증 정보 없이 수행한 서버 HTTP 진단이며 실제 브라우저 시험이 아닙니다. 500 응답의 원인은 확정하지 않았습니다. 유효 토큰의 경계 조회 성공·실서비스 CORS 허용/차단·서비스 중단을 어느 쪽도 증명하지 않습니다. 따라서 ‘FE 직접 호출 불가능’으로 단정하지 않되, 직접 호출을 운영 가능으로 확정하지도 않습니다.

API별 실제 쿼터·허용 도메인·캐시/상업 이용 조건·인증 응답은 서비스 키 발급 후 확인해야 합니다. 이전 FAQ의 일일 한도를 현행 계정 한도로 고정하지 않았습니다.

## 메인 API 서버 통합과 역할 분담

2026-10-20 사용자가 ‘통합된 메인 API 서버에서 처리되는 것’이라고 실행 위치를 명확히 했습니다. **후순위 검토를 재개한다면 경계 endpoint와 SGIS 연계 서비스를 메인 API 서버 안에 두는 방향**입니다. 기존 BE의 언어·프레임워크·배포 체계를 따르며 Node.js 추가를 요구하지 않습니다. 메인 BE 실제 코드/배포 상태는 확인하지 않았고 계약 검토·구현·연결은 보류 상태입니다.

```text
FE → 메인 API 서버의 경계 endpoint → 내부 SGIS 연계 서비스 → SGIS
FE ← 검증·변환한 경계/출처/기준일 ← 메인 API 서버
FE → 카카오 Polygon·지역명 라벨 표시
```

| 담당       | 역할                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| BE/데이터  | SGIS 인증·키/토큰 관리, H10 대응·기준일 확인, 경계 조회·CRS 변환·도형/대표점 검증, 출처·사용 조건, 캐시·호출 제한·장애 처리·운영 |
| FE         | 원본 H10 요청, 취소·재시도·로딩/없음/오류·응답 검증, 카카오 경계/라벨과 출처·기준일 표시                                         |
| FE/BE 공동 | 좌표 입력 필요 여부·H10 대응 방식·기존 DTO·오류·응답 시간·API URL/CORS·인증 계약 검토와 실서비스 인수                            |

외부 기능 경로는 기존 `GET /regions/{H10}/boundary` 초안을 우선 검토하고, 인증/SGIS 토큰·원본 API 호출은 서버 내부에 둡니다. 현재 FE 요청은 H10만 보내므로 좌표 기반 SGIS 조회에는 요청 계약 보완 또는 검증된 서버 코드 대응이 필요합니다. 기존 30초 응답 예산·GeoJSON/출처/기준일·`404 + BOUNDARY_NOT_AVAILABLE` 구분을 기준으로 협의하며 이번 작업에서 계약은 바꾸지 않았습니다. 분석/통계 endpoint와 경계 endpoint는 같은 메인 API 안에서 역할을 구분하고 경계 장애를 분석 실패로 취급하지 않습니다.

이 구성의 추가 범위는 **기존 서버 안의 경계 API 1개와 경계/SGIS 연계 모듈**입니다. 기존 환경설정·인증·배포·관측 체계는 검토 후 재사용할 수 있습니다. 서버 Secret은 BE 환경에서 관리하며 현재 FE에는 새 키/런타임/의존성을 추가하지 않습니다. 아래 FE 저장소 내부 Node 구성은 독립 실행이 필요한 경우의 대안으로 보존하며 검토 재개 시의 연계 위치는 메인 API 서버입니다.

## 프로젝트 내부에서 함께 실행하는 규모

2026-10-20 최초 ‘프로젝트 내부 실행’ 요청에 같은 FE 저장소의 `server/`에서 Node.js·TypeScript 경계 서버를 함께 실행하는 안을 설명했습니다. 이후 사용자가 위의 메인 API 통합 의도를 명확히 하여 이 안은 **메인 BE가 없거나 FE 저장소의 독립 실행이 필요한 경우의 대안**으로 보존합니다. 다음은 구현 전 설계이며 현재 `server/`나 새 실행 명령은 없습니다. SGIS 원본을 온라인으로 조회하므로 외부 SGIS 연결과 서비스 키는 계속 필요합니다.

| 항목      | 제안 규모와 역할                                                                                                                 |
| --------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 실행 단위 | 같은 저장소/배포의 경계 Node 서버 1개. 운영에서는 FE `dist/`도 같은 서버가 제공                                                  |
| 기능 API  | 경계 조회 1개. 기존 `/api/regions/{H10}/boundary` 재사용 지향이며 좌표 입력은 계약 협의 필요                                     |
| 상태 확인 | 필요하면 서버 상태 API 1개 추가. 인증·SGIS 토큰은 공개 API로 분리하지 않음                                                       |
| 서버 모듈 | 실행/설정, HTTP 경로/정적 제공, SGIS 인증·조회, 경계 대응/검증, 도형 변환, 캐시 등 대략 5~8개                                    |
| 저장소    | 초기 실증은 DB 없이 용량·만료를 제한한 메모리 캐시. 재시작 시 캐시가 사라짐                                                      |
| 예상 코드 | 서버 핵심은 수백 줄 규모를 예상하되 테스트·FE 연계·실행/빌드 설정은 별도. 측정치나 완료 보장이 아니며 코드 대응 규칙에 따라 증가 |

가능한 모듈 구분 예시입니다. 실제 파일 이름과 프레임워크는 구현 시 정하며 현재 존재하는 파일 경로가 아닙니다.

```text
server/
  index.ts       서버 시작과 종료
  config.ts      서버 환경변수 검증
  app.ts         경계 경로·정적 파일·오류 응답
  sgis.ts        토큰 재사용·SGIS 요청
  boundary.ts    지역 대응·기준일·출처·응답 검증
  geometry.ts    좌표 변환·복수 도형/구멍·라벨 좌표
  cache.ts       용량/만료 제한·동시 요청 합치기
```

- **개발 실행:** 루트 `pnpm dev`가 Vite와 Node를 함께 시작하도록 변경하고 경계 경로만 Vite에서 내부 Node로 프록시하는 방안을 권장합니다. 사용자가 실행할 명령은 하나지만 개발 프로세스는 둘입니다. 현재 명령은 Vite만 시작하며 [Vite 설정](../vite.config.ts)에도 프록시가 없습니다. Vite 공식 [개발 프록시](https://vite.dev/config/server-options.html#server-proxy)는 개발용 옵션이므로 운영 연결을 대신하지 않습니다.
- **운영 실행:** FE와 서버를 각각 빌드한 뒤 루트 실행 명령으로 Node 하나가 `dist/`와 경계 API를 함께 제공하도록 구성합니다. 이 실행 명령과 서버 빌드 설정도 추가해야 합니다. 소형 HTTP 프레임워크의 정적 제공 기능을 사용할 수 있습니다([Express 예시](https://expressjs.com/en/starter/static-files/)). 기존 Lightsail/Nginx를 쓰면 같은 배포 안의 내부 Node로 경계 요청만 전달할 수도 있습니다. 경계·알 수 없는 API 경로의 JSON 오류가 SPA fallback HTML로 바뀌지 않도록 순서를 분리합니다. [Vite 배포 문서](https://vite.dev/guide/static-deploy.html)에 따라 `vite preview`를 운영 서버로 사용하지 않습니다. `dist/`만 업로드하는 정적 배포 절차에는 Node 실행 환경이 추가됩니다.
- **FE 연결:** 현재 [경계 클라이언트](../src/lib/regionBoundary.ts)는 분석 데모일 때 경계 요청도 막습니다. 실제 경계 사용과 분석 데모를 분리해야 하며 `VITE_DEMO_MODE=false`만 켜는 우회는 카탈로그/분석까지 BE를 요구하므로 사용하지 않습니다. 현재 공통 API URL과 다른 분석 BE의 경로도 함께 검토합니다. 경계 DTO는 공유할 수 있지만 현재 검증 모듈은 Vite 환경설정/HTTP 모듈을 가져오므로 서버에서 통째로 import하지 않고 순수 검증을 분리하는 편이 적합합니다.
- **서버 역할:** Secret은 서버 설정에서만 읽고 브라우저 번들/응답에 넣지 않습니다. `VITE_` 접두사는 클라이언트에 노출되므로 사용하지 않습니다([Vite 환경변수 문서](https://vite.dev/guide/env-and-mode.html#env-variables)). 상위 요청의 총 시간 예산, 토큰 재발급 중복 방지, 캐시 용량/만료, 호출·응답 크기 제한, 공급자 HTTP 200 오류 본문도 처리해야 합니다. 상위 장애를 경계 없음으로 바꾸지 않습니다.

전체 규모에서 가장 불확실한 부분은 **SGIS 구역과 원본 H10의 실제 대응·경계 기준일 검증**입니다. 현재 순수 FE 프로젝트에 이 서버를 추가하면 저장소·실행 명령·배포를 통합할 수 있습니다. SGIS 실연결은 아직 미검증이며 전체 분석/AI BE는 별도 구현 대상입니다. 서버 성능·메모리·응답 시간은 실제 도형과 동시 요청을 측정한 뒤 정합니다. 이번 작업은 구조/규모 설명이며 서버 코드·환경변수·기존 API 계약은 변경하지 않았습니다.

## 사용자가 준비할 항목과 다음 검증

아래는 **향후 검토를 재개할 때의 참고 목록**입니다. 현재 키 발급·자료 준비나 구현 착수를 요청하는 내용이 아닙니다.

- 이 온라인 방식을 선택하면 **SHP ZIP 준비는 필요하지 않습니다.** [SGIS 개발지원센터](https://sgis.mods.go.kr/developer/html/main.html)에서 Data API 서비스 키 발급·사용 조건을 확인하는 단계가 대신 필요합니다. 실제 발급·약관 동의는 수행하지 않았습니다.
- 서비스 ID/Secret은 메인 API 서버의 BE 환경에서 관리하는 방향으로 담당자와 준비합니다. 현재 FE 환경변수에는 키를 추가하지 않습니다. 실제 값의 대화 전달은 필요하지 않습니다.
- 키가 준비되면 최소 지역들로 인증→좌표/코드→경계→CRS→H10 대응·기준일→현재 렌더러까지 실증합니다. 경계 근처·분동/통합 지역·복수 도형/구멍, 토큰 만료·한도·HTTP 200 오류 본문·상위 장애·동시 재시도도 확인합니다. 미지원/대응 미확인과 장애를 구분하고 확정된 요청/응답으로 문서를 갱신합니다.

현재 상태는 [SGIS Data API 연계의 후순위 검토·구현 보류](SGIS.md)입니다. 정적 파일안·FE 내부 Node 안도 대안으로 보존하며 현재 앱의 H10 경계 API 호출·데모 실제 경계 미제공·분석 계약·카카오맵 단일 사용은 그대로입니다. 실제 키/토큰·경계 수신·중계 구현·배포·브라우저/모바일 연결 검증은 미완료이고 현재 릴리스의 필수 인수 조건이 아닙니다.

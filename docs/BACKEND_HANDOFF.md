# 백엔드 개발 인계 · FE 연동 작업

작성일: 2026-10-12 (Asia/Seoul). 기준 구현은 `feature/1-map-workspace`의 `145a050`이며 [FE Draft PR #3](https://github.com/teojabi-groundbreakers/pickplace-frontend/pull/3)에 있습니다. 현재 FE 구현에 연결하기 위해 필요한 작업을 정리한 문서입니다. **BE 구현 완료나 팀 합의가 끝난 API 명세를 의미하지 않습니다.**

먼저 `GET /catalog`와 `POST /analyses`의 계약·행정동 코드·집계 단위를 FE/BE/AI 담당자가 확인한 뒤 구현합니다. 아래 P0는 최초 실서버 연동에 필요한 작업, P1은 이후 품질·정보 확장 작업입니다. 구체 담당자와 일정은 팀에서 지정합니다.

상세 필드의 원본은 [API 계약 초안](API.md), [분석 타입](../src/types/analysis.ts), [런타임 검증](../src/lib/validation.ts)입니다. 지역코드 출처·매핑 기준은 [REGION_CODES.md](REGION_CODES.md)를 따릅니다.

## 1. 현재 FE 동작과 역할 분담

| 사용자 동작                    | 현재 FE 처리                                                                         | BE에 필요한 처리                                |
| ------------------------------ | ------------------------------------------------------------------------------------ | ----------------------------------------------- |
| 첫 화면·지역/업종 검색         | 카카오맵 표시, 카탈로그를 받아 FE에서 검색·계층 선택. 첫 진입 시 분석 자동 실행 없음 | 지역·업종 카탈로그 제공                         |

지도는 카카오맵만 사용합니다. OSM·지도 선택·타일 대체 API는 필요하지 않습니다. 카카오 키·허용 도메인과 지도 조작은 [지도 문서](MAPS.md)에서 관리합니다. 분석 경계·시설 마커 데이터는 BE가 제공할 분석 결과와 연결합니다.

현재 수치·등급·진단은 데모입니다. 실제 API 모드는 오류를 데모 결과로 대신하지 않습니다. 프레임워크·DB·AI 서비스 연결 방식은 BE 팀에서 정하되 외부 계약을 먼저 맞춥니다.

2026-10-12 [행정동 경계 조사](MAPS.md#행정동-경계-데이터와-자체-표기)에서 카카오 공개 API의 경계 원본 조회 기능은 확인되지 않았습니다. BE-09는 사용 조건을 확인한 공식 경계 데이터 확보, 원본 H10과 데이터 코드의 대응 관계·기준일·CRS 관리가 필요합니다. SGIS는 기술 후보이며 운영 채택·인증·실응답·사용 조건은 미확정입니다. FE는 확보한 좌표를 카카오 `Polygon`으로 표시하고 스타일을 직접 제어할 수 있습니다.

## 3. 현재 FE가 호출하는 API

### 공통 규칙

- 기본 API URL은 `VITE_API_BASE_URL`이며 기본값 `/api` 뒤에 아래 경로를 붙입니다. 예: `/api/catalog`, `/api/analyses`.
- 요청 `Accept`는 `application/json`, 분석 본문은 `Content-Type: application/json`입니다.
- 성공 응답은 **객체 자체**를 반환합니다. `{ "data": ... }` 같은 래퍼는 현재 받지 못합니다.
- 현재 연동은 동기 응답입니다. 작업 ID만 주는 202 응답·폴링·진행률 API는 구현되어 있지 않습니다.
- 브라우저 요청 제한은 30초입니다. 새 분석 시작·저장한 분석 열기·분석 상태 훅 언마운트 시 이전 브라우저 요청을 취소하고 늦은 결과를 무시합니다. 단순 페이지 이동으로 훅이 해제되지는 않으며 서버 추론 작업의 취소까지 보장하지는 않습니다.
- 인증 토큰 헤더·교차 출처 쿠키 인증 처리는 아직 없습니다. 인증이 필요하면 로그인/권한/FE 요청 설정을 함께 합의합니다.

### GET /catalog

시·도 → 시·군·구 → 행정동, 업종 대분류 → 세부 업종 전체 목록을 반환합니다. 형태는 다음과 같습니다.

```text
{
  cities: [
    {
      code, name,
      districts: [
        {
          code, name,
          neighborhoods: [{ code, name, center: [위도, 경도] }]
        }
      ]
    }
  ],
  categories: [{ code, name, industries: [{ code, name }] }]
}
```

- 모든 `code`·`name`은 비어 있지 않은 문자열입니다. 운영 코드의 자릿수를 데모의 2/5/8자리에 맞출 필요는 없습니다.
- 현재 `cities`, `districts`, `neighborhoods`, `categories`, `industries`는 각 계층에 최소 1개가 필요합니다. 빈 카탈로그 지원이 필요하면 FE 상태/검증 계약을 먼저 조정합니다.
- `center`는 각 행정동의 대표 중심점입니다. 검색·지도 선택에 사용합니다.
- 지역 목록은 검색 편의 데이터입니다. 이 목록에 없다는 이유만으로 지도 조회 지역의 분석을 차단하면 안 됩니다. 실제 지원 범위 판단은 BE가 합니다.
- 업종 드롭다운은 이 응답의 업종코드를 그대로 사용합니다. `coffee` 등 FE 데모 코드를 운영 분류표로 확정한 상태가 아닙니다.
- FE는 서버 검색·페이지네이션을 호출하지 않습니다. 전국 목록을 분할하거나 검색 API로 바꾸려면 별도 FE 계약/구현이 필요합니다. 코드 중복도 피해야 합니다.

### POST /analyses

```json
{
  "regionCode": "1120067000",
  "industryCode": "coffee"
}
```

위 지역코드는 성수2가1동의 실제 카카오 H 조회 기록이며 전국 코드 검증 결과는 아닙니다. `coffee`는 요청 형태를 설명하는 데모 업종코드입니다. 실연동 시에는 서버 카탈로그의 업종코드를 사용합니다.

현재 보내는 필드는 **`regionCode`, `industryCode` 두 개뿐**입니다. 클릭 좌표·지역 이름·기간·조회 지표는 POST 본문에 포함하지 않습니다. BE는 지역코드로 대표 중심점과 분석 단위를 결정해야 합니다. 지도 둘러보기의 클릭 좌표는 FE 탐색 상태로 유지합니다.

카카오 조회의 **10자리 H 코드를 그대로 수용**해야 합니다. 내부 집계 코드로 변환하더라도 응답의 `request.regionCode`와 `request.industryCode`는 원본 요청 문자열과 완전히 같아야 합니다. 다른 코드로 바꿔 반환하면 FE가 결과를 거부합니다.

성공 시 `Analysis` 전체 객체를 반환합니다. 아래는 **형식 확인용 합성 수치 예제**이며 실제 상권 분석·모델 결과가 아닙니다. 월별 데이터는 간결하게 1개만 넣었고, 운영 제공 기간은 별도로 합의해야 합니다.

## 4. 응답에서 지켜야 할 조건

| 항목                       | 현재 FE 요구·표시 방식                                                 | BE/AI 확인할 내용                                                                 |
| -------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 필수 필드                  | `Analysis`의 모든 필드 필요. 빈 배열 허용과 필드 생략/`null`은 다름    | 누락 없이 응답 조립                                                               |
| 분석 `id`                  | 저장 토글·삭제의 식별자로 사용                                         | 서로 다른 결과의 ID 중복 방지. 캐시·재분석 시 동일/신규 ID 정책 합의              |
| `request`                  | 두 코드가 원본 요청 문자열과 완전히 일치                               | 내부 정규화 코드와 외부 요청 식별자 분리                                          |
| `source`                   | 검증 전에 필수. 운영 응답은 `api`                                      | FE가 최종 `api`로 표시해도 필드 생략 불가                                         |

| 점수 4종                   | 유한 숫자 0~100, 각각 `value/grade/description`                        | 종합·성장·적합도는 높을수록 긍정, **위험도는 높을수록 위험**. 산식·등급 구간 합의 |
| `factors`                  | 부호 있는 유한 숫자 `contribution`, 화면은 종합점수 기여 ‘점’으로 표시 | 긍정/부정 방향, 기준 점수·산출 방식. 퍼센트/위험도 기여와 혼용 금지               |
| `period`·`analyzedAt`      | 기준월 `YYYY.MM`, 분석 시각은 시간대가 있는 파싱 가능한 시각           | 데이터 기준월과 실행 시각 분리, 서로 다른 자료의 기준 시점 정합성                 |
| `trends`                   | 최소 1개, `month: YYYY-MM` 중복 없는 오름차순                          | 월 단위 제공. 분기 데이터는 현재 지원하지 않음                                    |
| 시계열 숫자                | 모든 행에 6개 지표 필요, 유한 숫자 0 이상                              | 숫자 문자열·음수·`null` 불가. 결측과 실제 0을 구분                                |
| `sales/averageSales`       | 점포당 월평균 매출, **만원**                                           | 같은 업종·기간·집계 방식. 비교 지역 범위와 가중 평균 기준 확정                    |
| `population`               | 일평균 유동인구, **명**                                                | 중복 집계·일평균 산식·측정 범위 확정                                              |
| `stores/openings/closures` | 점포·개업·폐업 수, **개**                                              | 기준 점포 범위·기간 집계 정의. FE는 현재 정수 여부까지 검사하지 않음              |
| `competition`              | `name/local/average/unit`, 수치는 유한 숫자 0 이상                     | 선택 지역·비교 지역의 동일 기준, 지표별 단위                                      |
| 좌표                       | `[위도, 경도]` 숫자 2개, 위도 ±90·경도 ±180                            | 카카오에 전달할 좌표로 변환. GeoJSON의 `[경도, 위도]`를 그대로 보내지 않음        |
| 지도 경계                  | `boundary` 좌표 배열, 빈 배열이면 중심 표시. 3개 이상이면 다각형       | 실제 행정동 경계 출처·기준일, 복수 경계/구멍은 별도 계약 필요                     |
| 시설                       | `id/name/type/position`, 종류는 `competitor/transport/facility`        | 유효한 좌표·중복 없는 ID·사용 가능한 데이터                                       |
| 선택 배열                  | `factors/competition/boundary/places/recommendations`는 빈 배열 허용   | 미제공이면 `[]` 반환. 필드 누락/`null`은 허용하지 않음                            |

6/12개월 선택은 재호출 없이 받은 배열의 마지막 6/12개를 표시합니다. 운영에서는 최근 12개월 제공을 협의하되, 현재 검증의 최소 기준은 1개입니다. 결측 월이 있으면 ‘12개 행’과 ‘연속 12개월’이 달라지므로 결측·불완전 월 처리와 데이터 부족 기준을 먼저 정합니다. 근거 없이 월을 0으로 채우거나 기간이 다른 통계를 섞지 않습니다.

AI 등급 문자열의 고정 enum·등급 경계·모델 버전·신뢰도 필드는 현재 계약에서 확정되지 않았습니다. 팀 규칙의 신뢰도 제공 요구를 반영하려면 표본 수·출처·모델 정보와 함께 별도 응답 필드 및 FE 표시를 합의해야 합니다. 기존 필드에 임의로 끼워 넣어 확정된 것처럼 처리하지 않습니다.

## 5. 지역코드와 데이터 준비 시 주의사항

- 분석 단위는 **행정동 H**입니다. 법정동 B나 가까운 다른 행정동으로 대신 분석하지 않습니다.
- 코드는 문자열로 저장·전달합니다. 자릿수만 보고 동일 코드 체계로 간주하거나 10자리 H 코드를 임의로 잘라 집계 데이터와 연결하지 않습니다.
- 카탈로그 행정동을 지도 조회와 같은 10자리 H 체계로 통일하는 방안을 먼저 협의합니다. 현재 FE는 카탈로그의 코드 자릿수를 강제하지 않지만, 두 경로의 대응 관계가 명확해야 합니다.
- 원본 기관·자료명·기준일·수집일·사용 조건, 카카오 H 코드와 통계 집계 코드의 대응표, 폐지/분동/통합 및 과거 통계 처리 기준을 데이터 담당자와 문서화합니다.
- 데모 불일치인 연남동 [이슈 #5](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/5), 성수2가1동 [이슈 #6](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/6)를 운영 데이터로 가져가지 않습니다. 8자리 뒤 `00` 매칭은 FE 데모 전용입니다.
- 유효 코드 여부, 서비스 지원 범위, 분석 표본 부족을 BE가 구분합니다. FE 목록 밖 지역도 실제 분석 요청이 들어옵니다. 잘못된 입력·모델 장애를 모두 데이터 부족으로 감추지 않습니다.

공식 자료 확인 경로와 기존 실제 조회 기록은 [지역코드 기준](REGION_CODES.md)에 있습니다. 이 문서는 새 공식 코드 목록을 내려받아 검증한 결과가 아닙니다.

## 6. 오류·시간 제한·운영 연결

데이터 부족 응답의 계약 초안은 다음과 같습니다.

```http
HTTP/1.1 422 Unprocessable Content
Content-Type: application/json
```

```json
{
  "code": "INSUFFICIENT_DATA",
  "message": "분석 표본이 부족합니다."
}
```

현재 FE는 비정상 HTTP 응답의 **`code`**로 데이터 부족 화면을 구분합니다. 422만 반환하고 이 코드가 없으면 일반 오류이며, 다른 오류 상태라도 이 코드가 있으면 데이터 부족으로 표시됩니다. BE는 상태와 코드 조합을 일관되게 제공하고, 나머지 오류 코드·상태는 담당자 간 확정합니다.

서버의 `message`는 현재 화면에 그대로 표시되지 않습니다. FE가 `INSUFFICIENT_DATA` 또는 일반 오류·타임아웃·네트워크 오류의 고정 안내를 사용합니다. 미지원 지역·인증 만료·요청 제한 등을 구체적으로 안내하려면 오류 코드별 FE 분기를 함께 추가해야 합니다. 잘못된 성공 JSON·요청 조건이 다른 결과는 FE 형식 오류로 처리됩니다.

30초보다 긴 분석이 필요하면 작업 생성·상태 조회·실패/취소·결과 조회 계약과 FE 변경을 먼저 합의합니다. 재시도로 같은 분석이 여러 번 실행될 때의 비용·캐시 유효기간·중복 처리와 브라우저 취소 후 서버 작업의 처리 정책도 정합니다.

연결 시 BE가 전달할 정보:

- 개발/검증/운영 API 기준 URL과 FE 허용 출처, 프록시 사용 여부
- 사용 가능한 테스트 행정동·업종, 데이터 기준월, 데이터 부족/장애 재현 방법
- 확정된 명세·응답 예제·오류 코드표·코드 매핑 및 데이터 갱신 주기
- 인증 도입 여부와 필요한 FE 요청 설정, 서버 실행 방법·환경변수 이름(실제 비밀값 제외)

FE 실제 API 연결 설정 예시:

```dotenv
VITE_DEMO_MODE=false
VITE_API_BASE_URL=/api
VITE_KAKAO_MAP_APP_KEY=발급받은_JavaScript_앱_키
```

별도 서버 출처를 쓴다면 `VITE_API_BASE_URL`을 해당 기준 URL로 바꾸고 CORS를 맞춥니다. 운영은 HTTPS·프록시 경로를 함께 확인합니다. 서버 비밀키·DB 비밀번호·AI 서비스 인증값은 VITE 환경변수나 응답에 넣지 않습니다. 정적 FE 배포 절차는 [FRONTEND.md](FRONTEND.md#정적-배포)를 참고합니다.

## 7. FE와 함께 확인할 인수 시나리오

아래 항목은 **실서버 연결 후 수행할 체크리스트**입니다. 현재 모의 테스트 통과를 BE 연동 완료로 간주하지 않습니다. 응답 오류·장애는 검증 환경에서 재현합니다.

- [ ] 실제 API 모드에서 카탈로그 로드·계층 선택·지역 검색·업종 선택이 된다. 목록 실패 후 재시도가 된다.
- [ ] 상단 분석과 우클릭 분석이 동일한 경로를 사용한다. 카탈로그 밖의 유효한 10자리 H 코드와 서버 제공 업종으로 요청할 수 있다.
- [ ] 응답의 두 요청 코드가 원본과 같다. 내부 집계 코드로 바꿔 반환한 결과는 FE에서 거부된다.
- [ ] 점수 4종·요인·차트·경쟁 비교·진단·중심점/시설이 같은 지역·업종·기준으로 표시된다. 위험도 방향과 수치 단위를 확인한다.
- [ ] 받은 시계열로 6/12개월·지표를 전환한다. 실제 제공 기간·결측 처리와 UI 설명이 일치한다.
- [ ] 422 + `INSUFFICIENT_DATA`는 데이터 부족, 그 외 서버 오류는 오류/재시도로 표시된다. 실제 API 실패를 데모 결과로 대신하지 않는다.
- [ ] 숫자 문자열·필드 누락·빈 `trends`·중복/역순 월·잘못된 좌표가 형식 오류로 처리된다.
- [ ] 30초 초과·연결 실패·재시도·취소·늦은 이전 응답을 확인한다. 취소 후 서버 작업 처리와 중복 비용 정책도 확인한다.
- [ ] ‘이 지역 둘러보기’에서는 분석 POST가 발생하지 않고 클릭 위치가 확대된다.
- [ ] 분석 저장·재열기·상단 재분석에서도 원본 코드와 업종이 유지된다. 저장이 브라우저 로컬 기능임을 확인한다.
- [ ] 운영 FE에서 API 경로·CORS/프록시·HTTPS와 카카오 허용 도메인이 정상이다. 비밀값이 FE 번들·응답에 없다.

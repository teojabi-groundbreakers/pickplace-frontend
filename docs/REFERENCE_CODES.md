# BE 기준정보 코드 대응 준비

[이슈 #16](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/16)의 선택 지역 위치 확인을 위한 FE 준비 코드다. 코드 대응 스냅샷과 검증 함수를 사용해 목록 선택 화면에서 장소 좌표를 카카오 행정동 역조회로 확인한 뒤 지도 이동에 연결한다.

## 출처와 범위

[고정 스냅샷](../src/data/seoulReferenceCodes.json)은 사용자가 제공한 BE `src/main/resources/reference-data/seoul-reference.json`에서 지역 대응 필드를 추출한 자료다. 버전 `seoul-reference-20262-mois-20261012-v1`, 행정안전부 코드표 대조 기준일 2026-10-12, 원본 SHA-256 `da5e5e5aaccc7f6ca0e2706dc925a6076274491211060bd386388759e35ec796`을 기록한다. BE의 자료 준비 기록에는 출처가 서울 열린데이터광장·서울신용보증재단·[행정안전부 코드표](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=130109), 원천 수집일이 2026-10-15, 공식 코드 대조일이 2026-10-16으로 기재되어 있다. 공식 코드 대조는 BE 기록을 근거로 하며 FE가 원본 코드표를 별도 검증한 것은 아니다. 지문 기록은 FE 실행 중 BE 원본을 재검증한다는 뜻이 아니다.

BE 목록의 자치구 코드·이름과 행정동 원천 코드·이름·소속·상태·버전이 스냅샷과 모두 일치하고 상태가 `CURRENT`인 경우에만 공식 H10 대응을 반환한다. 8자리 코드를 자르거나 `00`을 붙이거나 이름만으로 H10을 추정하지 않는다. 스냅샷은 공식 중심점과 행정동 경계를 제공하지 않는다.

## 남은 사항

이 자료는 2026-10-12 기준으로 고정되어 이후 변경을 자동 반영하지 않는다. 새 BE 기준정보 버전을 사용할 때 출처·기준일·코드 대응을 다시 검토해야 한다. 장소 좌표의 카카오 행정동 역조회 결과와 H10 일치, 지도 UI·요청 경합은 모의 테스트로 확인하며 실제 카카오 연동에서도 확인이 필요하다. 원천 자료의 이용 조건 독립 확인, FE/BE 담당자 검토·실제 서버·모바일·팀 리뷰 및 병합은 미완료다.

## 사용자 제공 법정동 자료 대조

2026-11-08 사용자가 제공한 `법정동코드 전체자료.txt`를 기준정보 검토에 활용했다. 파일은 CP949·탭 구분이며 `법정동코드`, `법정동명`, `폐지여부` 열의 53,403건(존재 20,560건, 폐지 32,843건)을 포함한다. 원본 SHA-256은 `962fd4cdfb6ccf2887b745eb97db55f71112b9f9a32c1f8fbd7692fb069b1df0`이다. 파일 내부에는 제공기관·기준일·이용 조건이 표기되지 않아 다운로드 출처와 기준일은 별도 확인이 필요하다. 원본을 저장소에 복사하지 않았다.

- 서울에 한정해 현존하는 구 레코드의 이름과 10자리 법정동 코드의 앞 5자리를 기존 서울 자치구 스냅샷의 코드·이름과 대조한 결과 25개 모두 일치했다. 이는 서울 구 목록의 자료 간 대조이며 전국 코드 호환성이나 최신성 검증은 아니다.
- 이 파일은 **법정동** 자료다. 서빙고동은 이 파일에서 `1117013300`, 기존 서울 행정동 스냅샷의 공식 H10은 `1117069000`으로 다르다. 법정동을 행정동 분석 코드로 쓰거나 이름만으로 두 코드를 대응하지 않는다.
- 시·도·시·군·구의 명칭과 지역 체계를 검토하는 데 활용할 수 있다. 다만 세종특별자치시의 코드 표현과 일반 시 아래 구처럼 계층 예외가 있으므로 고정 자리수를 자르는 방식으로 전국 목록을 확정하지 않는다. 해당 자료의 기준일·상위 관계와 BE 기준정보의 버전을 검증해야 한다.
- [행정표준코드관리시스템 법정동 목록](https://www.code.go.kr/stdcode/regCodeL.do?menuNo=101010100010)은 같은 종류의 법정동 코드 검색을 제공한다. 이 페이지의 존재만으로 사용자 파일의 출처·기준일이 확인된 것은 아니다. 같은 시스템의 [FAQ](https://code.go.kr/qna/faqL.do)는 행정동 전체코드와 법정동·행정동 매핑을 행정안전부 주민등록주소코드 변경내역에서 확인하도록 안내한다.
- 전국 행정동 선택·분석에는 검증된 행정동 자료와 원천 통계 코드 대응, BE 지역 목록·분석 API 및 FE 전국 위치 확인이 별도로 필요하다. 이번 대조는 서비스의 지역 선택지나 분석 코드에 적용하지 않았다.

## 행정안전부 원본과 재현 가능한 대조

2026-11-08 [행정안전부 2026-10-30 기준 게시물](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=130674)에서 현행 주소코드 ZIP을 확보했다. 게시물의 기준일은 10월 30일이고 ZIP 및 내부 파일명은 `20261026`이므로 둘을 구분한다. 기존 FE 스냅샷의 기준 시점인 [2026-10-12 게시물](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardArticle.do?bbsId=BBSMSTR_000000000052&nttId=130109)의 현행 ZIP도 별도로 확보했다. 원본은 FE·BE·AI 폴더 밖 `PickPlace/reference-data/`에 두고 Git에 포함하지 않는다.

| 원본 파일            | SHA-256                                                            | 용도                                          |
| -------------------- | ------------------------------------------------------------------ | --------------------------------------------- |
| `jscode20261012.zip` | `3702ee001f131968983fbba1e08c6bffc89f6ee4377de327e5eff6946b1098d7` | 기존 FE 스냅샷과 같은 기준일의 공식 자료 대조 |
| `jscode20261026.zip` | `cce7299a01bfb29edc234884dbd4afa87b4a3a899ae3aefb9d6e4d0fe7b82509` | 10월 30일 게시물의 현행 공식 자료 대조        |

두 ZIP의 `KIKcd_H`는 행정기관·행정동 코드, `KIKcd_B`는 법정동 코드, `KIKmix`는 행정기관과 관할 법정동의 관계다. 원본 TXT는 CP949 고정폭이며 ZIP 안의 XLSX는 같은 내용을 열 단위로 제공한다. 상세 이용·재배포 조건은 별도로 확인해야 하므로 원본이나 파생 목록을 서비스에 배포하지 않았다.

두 공식 원본 각각과 기존 서울 스냅샷을 대조한 결과 `CURRENT` 422건의 H10·공식명·서울 소속 구가 모두 일치했고 불일치는 없었다. `LEGACY` 3건은 현행 ZIP 대조에서 별도 집계했으며 과거 코드와 공식 원본의 일치 여부를 검증한 것은 아니다. 최신 ZIP의 행정기관은 상위 기관을 포함해 3,926행이고 읍·면·동 명칭이 있는 행은 3,630개다.

최신 `KIKmix`에서 읍·면·동 명칭이 있는 관계만 집계했을 때 법정동 코드 757개는 복수 행정동과, 행정동 코드 2,310개는 복수 법정동과 연결된다. 예를 들어 서빙고동 행정동 `1117069000`은 서빙고동 법정동 `1117013300` 등을 관할한다. 이는 법정동↔행정동의 **다대다 관할 관계**로, 서울 통계 원천 코드↔H10의 검증된 관계와는 별개다. 상위 출장소 행에는 일반 법정동 목록에 없는 코드가 포함될 수 있어 전체 행을 무조건 일반 법정동으로 처리하지 않는다.

표준 라이브러리만 사용하는 [검증 도구](../scripts/check_official_reference.py)는 원본 ZIP과 FE 스냅샷을 읽기 전용으로 비교한다. H와 관할 파일의 기준일, XLSX 헤더·코드 형식·참조 관계와 스냅샷 중복을 확인하고 코드·이름 불일치 및 다대다 관계를 요약한다. 파일은 다운로드하거나 수정하지 않는다.

```sh
python3 scripts/check_official_reference.py \
  --archive ../reference-data/jscode20261026.zip \
  --snapshot src/data/seoulReferenceCodes.json
```

일치 시 종료 코드 0, 현행 스냅샷 불일치 시 1, 입력 파일이나 형식 오류 시 2를 반환한다. 실제 두 ZIP의 일치 결과와 명칭 불일치·손상 ZIP·H/관할 파일 기준일 불일치의 실패를 검증했다. 이 검사는 공식 코드의 존재와 이름·소속 비교이며 통계 원천 코드와 H10 사이의 독립적인 매핑 검증, 전국 선택이나 실분석 완료를 뜻하지 않는다. 새 BE 버전 도입 시 원천 데이터 대응·기준일·지역별 계층·위치 확인 계약을 별도로 합의하고 새 원본으로 다시 검증한다.

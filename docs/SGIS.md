# SGIS 행정동 경계 연계 검토

공식 문서 확인일: 2026-10-20 (Asia/Seoul). [이슈 #10](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/10)의 후속 조사입니다. 사용자가 SGIS 사용 방향을 요청한 뒤 **필수사항이 아닌 후순위 검토사항으로 남기도록 정정**했습니다. 도입 확정·착수 지시·배포 선행 조건이 아니며, 실제 인증·경계 수신·BE 구현·FE 연결·배포는 미완료입니다.

## 검토 방향과 범위

| 항목              | 검토 내용                                                          |
| ----------------- | ------------------------------------------------------------------ |
| 상태/우선순위     | 후순위 검토·구현 보류. 현재 필수 개발·배포를 막지 않음             |
| 경계 출처 후보    | SGIS Data API의 행정구역경계                                       |
| 재개 시 연계 위치 | 프로젝트의 통합 메인 API 서버 내부 경계 서비스                     |
| 지도/표시         | 기존 카카오맵의 `Polygon`·`CustomOverlay` 유지                     |
| 자료 준비         | 사전 SHP/GeoJSON 파일 준비를 요구하지 않는 온라인 API 방식         |
| 대안              | VWorld·정적 파일·FE 저장소 내부 Node 안은 비교 기록으로 보존       |
| 적용 범위         | 행정동 경계 연계. 매출·유동인구·AI 데이터 공급/계약은 별도 BE 작업 |

```text
FE의 원본 H10 경계 요청
  → 메인 API 서버: 인증·SGIS 코드 대응·경계 조회·검증/좌표 변환
  → 기존 RegionBoundary 응답
  → FE 검증·상태 처리·카카오 경계/지역명/출처 표시
```

위 흐름은 재개 시 검토할 설계이며 구현 계획 확정이 아닙니다. SGIS 지도 SDK를 FE에 도입하는 안은 아닙니다. 공식 [지도 SDK 문서](https://sgis.mods.go.kr/developer/html/newOpenApi/api/mapApi/startMapAPI.html)의 2025-12-31 종료 예정 안내를 Data API 전체 종료로 확대하지 않으며 실제 SDK 종료 상태도 확인하지 않았습니다.

## 공식 명세에서 확인한 API

기준 호스트는 `https://sgisapi.mods.go.kr`입니다. 아래는 문서 확인 결과이며 인증된 실제 호출 예제가 아닙니다.

| 용도               | 경로                                       | 확인한 요청·응답                                                        |
| ------------------ | ------------------------------------------ | ----------------------------------------------------------------------- |
| 인증               | `/OpenAPI3/auth/authentication.json`       | `consumer_key`·`consumer_secret` → `accessToken`·`accessTimeout`        |
| 좌표의 행정동 후보 | `/OpenAPI3/addr/rgeocodewgs84.json`        | `accessToken`, EPSG:4326 `x_coor`·`y_coor`, `addr_type=20`              |
| 행정동 경계        | `/OpenAPI3/boundary/hadmarea.geojson`      | `accessToken`·`year`·`adm_cd`, 해당 동만 조회하도록 `low_search=0` 명시 |
| 좌표 변환          | `/OpenAPI3/transformation/transcoord.json` | `accessToken`·`src`·`dst`·`posX`·`posY`                                 |

근거: [인증](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/basics.html), [주소/경계](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/addressBoundary.html), [좌표 변환](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/coord.html).

경계 명세의 연도 범위는 **2000~2025**, 읍면동 `adm_cd`는 **SGIS 8자리**입니다. `low_search`의 기본값은 1이므로 대상 동 조회에는 0을 명시합니다. 응답은 `FeatureCollection`이며 FE 객체로 정규화해야 합니다. 문서의 범위를 실제 계정의 조회 성공·운영 최신 연도 확인으로 대신하지 않습니다.

## 재개 시 BE·FE 기술 검토 항목

1. **인증:** 메인 BE에서만 서비스 ID/Secret을 읽고 토큰을 재사용합니다. 공식 [인증 사용방법](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/authAndUseApi.html)은 유효기간 4시간을 안내합니다. `accessTimeout` 실제 형식/단위와 만료 오류를 실증하고 동시 재발급·무한 재시도를 막습니다. 키/토큰을 FE 번들·응답·로그에 노출하지 않습니다.
2. **지역 대응:** 카카오 원본 H10과 SGIS 코드를 구분합니다. 좌표 역지오코딩은 코드 후보를 찾는 수단이며 H10 절삭·법정동 대체·이름 일치만으로 대응을 확정하지 않습니다. 분동/통합과 경계연도·코드 시점을 검증하고 대응 미확인 도형에 요청 H10을 붙여 반환하지 않습니다.
3. **경계/좌표:** 검증한 SGIS 코드·연도로 조회해 모든 폴리곤/구멍을 보존합니다. 경계 예제 좌표는 경위도 범위를 벗어나며 해당 절에 CRS가 명시되지 않았습니다. 역지오코딩의 WGS84 설명이나 다운로드 SHP의 EPSG를 경계 API에 대입하지 않습니다. 실제 CRS 확인 후 WGS84 `[경도, 위도]`로 변환하고 위상·대표점 내부 포함을 검사합니다. 꼭짓점별 변환 API 호출 비용을 평가하고 서버 일괄 변환도 검토합니다.
4. **FE 응답:** 기존 [경계 API 초안](API.md#get-regionsh10boundary)·[타입](../src/types/boundary.ts)에 맞춥니다. 원본 H10·`regionType: H`·지역명·EPSG:4326 geometry·내부 대표점·출처·실제 `boundaryDate`가 필요합니다. 경계 명세에는 정확한 일자 필드가 없어 요청 연도나 SHP 기준일로 날짜를 임의 생성하지 않습니다. 공식 일자를 확보하거나 날짜 정밀도 계약을 FE/BE가 합의해야 합니다.
5. **캐시/장애:** 사용 조건 확인 후 코드·경계연도·변환 버전별로 용량/만료를 제한한 캐시와 동시 요청 합치기를 적용합니다. HTTP 성공만 보지 않고 `errCd`·응답 구조·도형을 검사합니다. 만료·한도·상위 장애와 경계 없음은 구분하며 데모 도형으로 대체하지 않습니다. 서버 시간 예산은 FE의 현재 30초 제한 안에서 설계합니다.

현재 [FE 요청](../src/lib/regionBoundary.ts)은 `GET /regions/{H10}/boundary`에 **H10만 전달**합니다. 좌표 기반 조회에는 클릭 좌표 입력 추가 또는 검증된 서버 대응 관계가 필요합니다. 이번 문서화에서는 URL·필드·DTO·오류 코드를 바꾸지 않았습니다. 기본 데모가 경계 요청을 막는 동작도 유지합니다. 실제 경계를 도입한다면 분석 데모와 실제 경계 사용을 분리하는 FE 작업도 검토해야 합니다.

데모 카탈로그의 8자리 코드는 현재 H10 경계 조회 훅의 대상이 아니며 SGIS 8자리와 같은 코드로 취급하지 않습니다. 자릿수 일치만으로 매핑하거나 `00`을 붙여 조회하지 않습니다.

## 재개 시 키·운영 조건 확인

지금 사용자나 BE 담당자에게 키 발급·파일 준비·구현을 요청하지 않습니다. 아래는 향후 도입 검토를 재개할 때의 참고 사항입니다.

- 공식 [키 발급 절차](https://sgis.mods.go.kr/developer/html/newOpenApi/app/apply.html)는 테스트키 발급·개발 후 상용키 신청/승인을 안내합니다. 계정/BE 담당자가 서비스 등록·사용 목적·운영 조건을 확인합니다. 실제 로그인·신청·약관 동의·발급은 수행하지 않았습니다.
- BE 설정 이름의 예시는 `SGIS_CONSUMER_KEY`, `SGIS_CONSUMER_SECRET`, `SGIS_BOUNDARY_YEAR`입니다. **제안 이름이며 이 FE 저장소에 추가/구현한 환경변수가 아닙니다.** 실제 값의 대화 전달은 필요하지 않고 `VITE_*`에 넣지 않습니다.
- 공개 [API 약관](https://sgis.mods.go.kr/developer/html/newOpenApi/app/rules.html)은 키당 일일 50,000회·키 공유 금지·사전 승낙 없는 영업활동 제한을 명시하며 시행일은 2015-01-01로 표시됩니다. 이 수치를 현행 계정의 보장 한도로 고정하지 않습니다. 실제 상용 승인·호출/재시도 예산·중계/캐시·가공/출처 조건은 발급 계정과 제공기관 기준으로 확인합니다.

## 재개 시 역할과 실연결 확인 항목

| 담당       | 도입 검토를 재개하면 확인할 작업                                                |
| ---------- | ------------------------------------------------------------------------------- |
| BE/데이터  | 키·토큰·SGIS 어댑터·H10 대응·CRS/기준일·대표점·출처·캐시·오류/운영              |
| FE         | 합의된 계약 연결, 분석 데모/경계 설정 분리, 취소/재시도·카카오 표시·실기기 확인 |
| FE/BE 공동 | 좌표 입력·코드/기준일·DTO·URL/인증·시간 예산 검토와 인수                        |

- [ ] 테스트키 인증·토큰 만료/재발급과 실제 경계 GeoJSON 수신
- [ ] 여러 지역의 H10↔SGIS 코드/경계연도·실제 CRS·기준일 검증
- [ ] 경계 근처·분동/통합·섬/복수 도형·구멍과 라벨 위치 확인
- [ ] 경계 없음·만료·한도·HTTP 200 오류 본문·상위 장애·취소/동시 재시도 확인
- [ ] 메인 API 정상/없음/실패 응답의 FE 연결과 실제 카카오/모바일 표시 확인
- [ ] 상용 키/사용 조건·출처·배포와 관련 담당자 계약 검토

위 항목은 **미검증·보류된 검토 목록**이며 현재 릴리스의 필수 인수 조건이 아닙니다. 공식 문서 확인을 도입 확정·실제 연결·운영 승인·팀 리뷰/병합 완료로 기록하지 않습니다. 비교 근거는 [온라인 경계 조사](BOUNDARY_ONLINE.md), 전체 BE 작업은 [인계 문서](BACKEND_HANDOFF.md)를 참조합니다.

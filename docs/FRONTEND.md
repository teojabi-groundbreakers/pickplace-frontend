# FE 구성·실행·배포

React 19 · TypeScript · Vite 기반 상권 분석 FE 기본 구현입니다.

## 현재 구현 상태

## 공통 사이드바

2026-10-09 사용자 요청에 따라 지도·저장한 분석·이용 가이드의 사이드바를 같은 `Layout`과 CSS로 통일했습니다.

- 데스크톱과 760px 초과 화면은 **76px 아이콘 메뉴**로 시작합니다. 하단 `>` 버튼을 누르면 **224px**로 펼쳐 로고 이름·메뉴명·저장 수·가이드 카드·하단 안내를 표시합니다. `<`로 다시 접습니다.
- 로고는 상단 22px, 높이 39px이며 로고 아래 34px 뒤 메뉴가 시작됩니다. 메뉴 높이 49px·간격 8px과 아이콘의 가로 위치는 접기/펼치기와 페이지 이동에 관계없이 같습니다. 메뉴를 밀어내던 `WORKSPACE` 제목과 화면별 사이드바 크기 덮어쓰기를 제거했습니다.
- 접힘 상태는 `Layout`의 화면 상태로 유지해 메뉴를 눌러 이동해도 바뀌지 않습니다. 새로고침이나 직접 진입은 접힌 상태로 시작하며 별도 브라우저 저장은 하지 않습니다.
- 하단 버튼은 설명 영역과 분리합니다. 펼쳤을 때 공간이 부족하면 가이드 카드·하단 안내 영역만 스크롤하고 로고·메뉴·접기 버튼은 유지합니다. 본문 폭과 알림의 중앙 위치는 공통 `--sidebar-width`를 따릅니다.
- 하단 접기/펼치기는 별도 박스 배경·테두리·그림자 없이 사이드바 배경과 이어지게 표시합니다. 마우스를 올려도 배경은 같고 아이콘·라벨의 불투명도만 바뀝니다. 44px 높이의 클릭 영역과 기존 키보드 포커스 표시는 유지합니다.
- 760px 이하에서는 기존 상단 메뉴 버튼으로 224px 전체 메뉴를 열고 닫습니다. 하단 데스크톱 토글은 숨기며 페이지 선택·닫기·배경 누르기로 모바일 메뉴를 닫습니다. 모바일 열림과 데스크톱 펼침 상태는 별도입니다.
- 아이콘만 보여도 링크의 접근 가능한 이름을 유지합니다. 토글에는 동작 이름·`aria-expanded`·`aria-controls`가 있고 Enter/Space로 조작할 수 있습니다. 지도 폭 변화는 기존 카카오 `ResizeObserver`의 `relayout`, Leaflet의 `invalidateSize`로 처리합니다.

검증: 공통 메뉴의 직접 진입·페이지 이동 중 상태 유지·재접기·키보드·모바일 메뉴 상태를 자동 테스트 5개로 확인했습니다. Chrome에서 지도 화면의 접기/펼치기와 로고·아이콘 위치 유지, 저장 화면의 펼친 상태 유지 및 재접기, 가이드의 접힌 메뉴 배치를 확인했습니다. 400px 폭의 기기 미리보기에서 모바일 메뉴 열기와 저장 화면 이동을 확인했으나 전체 모바일 높이·실제 모바일/태블릿 기기 검증은 남아 있습니다. 검증용 개발자 도구는 닫고 데스크톱 화면으로 복구했습니다.

## 실행

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

기본값은 명시적인 **데모 모드**입니다. 서버 없이 일부 예시 지역·업종의 분석 흐름을 확인할 수 있습니다. 첫 화면은 지도 탐색이며 분석 버튼을 누른 후에 결과가 표시됩니다. 점수·통계·AI 문구·시설 마커·경계는 가상 예시입니다. 배경 지도는 카카오지도/별도 타일/OSM을 선택할 수 있으며, 외부 연결 없이 표시하는 기본 위치도도 제공합니다.

## 지도 설정

지도 선택 방법·우클릭 분석·둘러보기와 장애 대응은 [MAPS.md](MAPS.md)에 있습니다. 실제 API 모드에서는 조회된 행정동을 FE 지역 목록으로 제한하지 않습니다. 둘러보기는 배경지도를 확대하며 별도의 점포 검색 API를 호출하지 않습니다. `auto` 기본값은 카카오 앱 키가 있으면 카카오, 별도 타일 설정이 있으면 해당 타일, 모두 없으면 OSM을 초기 선택합니다. OSM 공용 서버를 사용하지 않으려면 `kakao`, `custom` 또는 `schematic`을 명시하세요. 명시한 공급자의 설정이 없거나 연결에 실패하면 기본 위치도로 전환할 수 있으며 OSM으로 암묵 전환하지 않습니다.

```dotenv
VITE_MAP_PROVIDER=kakao
VITE_KAKAO_MAP_APP_KEY=발급받은_JavaScript_앱_키
```

카카오지도 실제 연결에는 JavaScript 키와 서비스 URL 등록이 필요합니다. 키 종류·허용 도메인 오류는 [지도 연결 오류 확인 순서](MAPS.md#연결-오류-확인-순서)를 따릅니다. 기본 위치도는 실제 도로지도와 구분하여 표시합니다.

## 구조

```text
src/components/  공통 UI, 검색, 점수, 차트, 지도, 인사이트
src/pages/       분석, 저장 목록, 이용 가이드
src/lib/         설정, HTTP 클라이언트, 검증, 요청 상태, 로컬 저장
src/data/        데모 목록·분석 fixture
src/types/       BE 연동 타입
src/test/        컴포넌트·API·상태 테스트
```

디자인 토큰은 `src/index.css`, 공통 반응형 스타일은 `src/App.css`, 지도 워크스페이스 스타일은 `src/styles/map-workspace.css`에 있습니다. 지도는 별도 청크로 지연 로딩합니다. 지역 조회는 `src/lib/regionLookup.ts`, 지역 검색은 `src/components/MapSearch.tsx`에서 처리합니다.

## 정적 배포

`pnpm build`의 `dist/`를 정적 호스팅 또는 Lightsail Nginx에 업로드합니다. BrowserRouter를 사용하므로 모든 FE 경로가 `index.html`로 fallback되어야 합니다. Nginx 예:

```nginx
server {
    listen 80;
    server_name your-domain.example.com;
    root /var/www/pickplace;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    # 동일 출처 API를 사용할 경우 FE fallback과 분리합니다.
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

HTTPS·실제 서버 주소·도메인·API 배포는 운영 환경에 맞춰 설정합니다. 이 저장소 변경에는 실제 운영 배포가 포함되지 않습니다.

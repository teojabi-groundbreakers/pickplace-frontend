# FE 구성·실행·배포

React 19 · TypeScript · Vite 기반 상권 분석 FE 기본 구현입니다.

## 현재 구현 상태

화면 흐름은 **지도 탐색 → 지역·업종 선택 → 분석 요청 → 결과 확인**입니다. 첫 화면은 넓은 지도이며 상단 검색창에서 조건을 고릅니다. 결과는 지도 오른쪽 또는 좁은 화면의 하단 패널에 표시합니다. 첫 진입 시 결과를 자동 생성하지 않습니다. 저장한 분석을 다시 열면 해당 결과와 검색 조건을 복원합니다.

## 공통 상단 바

2026-10-13 사용자 요청에 따라 지도·저장한 분석·이용 가이드의 상단 바 크기를 기존 지도 기준으로 통일했습니다.

- 소개를 포함한 모든 페이지는 `Layout`의 `.topbar`를 사용하며 높이는 **56px**, 좌우 여백은 **24px**입니다. 760px 이하에서도 높이는 같고 좌우 여백만 **16px**로 줄어듭니다. 전역 `box-sizing: border-box`에 따라 하단 테두리 1px도 높이에 포함됩니다.
- `src/App.css`의 `.app-shell`에 `--topbar-height`와 `--topbar-padding-inline`을 정의합니다. 지도 전용 높이/여백과 1250px·760px의 중복 덮어쓰기를 제거해 페이지 이동이나 사이드바 접기/펼치기로 기준이 달라지지 않습니다.
- 지도 본문의 높이는 `calc(100dvh - var(--topbar-height))`이며 일반 본문의 최소 높이도 같은 토큰을 참조합니다. 일반 화면은 이전 계산에서 상단 바를 제외한 65px 여유를 유지합니다.
- 제목·아이콘·우측 상태 표시는 기존 공통 배치를 사용합니다. 모바일 메뉴와 아이콘 숨김·간격 축소, 본문 자체의 좌우 여백, 인쇄 시 상단 바 숨김은 기존 규칙을 따릅니다.

검증 범위·실제 화면 확인 제한은 [작업 이력](WORKLOG.md)에 기록합니다.

## 공통 사이드바

2026-10-09 사용자 요청에 따라 지도·저장한 분석·이용 가이드의 사이드바를 같은 `Layout`과 CSS로 통일했습니다.

- 데스크톱과 760px 초과 화면은 **76px 아이콘 메뉴**로 시작합니다. 하단 `>` 버튼을 누르면 **224px**로 펼쳐 로고 이름·메뉴명·저장 수·서비스 소개 배너·하단 안내를 표시합니다. `<`로 다시 접습니다.
- 로고는 상단 22px, 높이 39px이며 로고 아래 34px 뒤 메뉴가 시작됩니다. 메뉴 높이 49px·간격 8px과 아이콘의 가로 위치는 접기/펼치기와 페이지 이동에 관계없이 같습니다. 메뉴를 밀어내던 `WORKSPACE` 제목과 화면별 사이드바 크기 덮어쓰기를 제거했습니다.
- 접힘 상태는 `Layout`의 화면 상태로 유지해 메뉴를 눌러 이동해도 바뀌지 않습니다. 새로고침이나 직접 진입은 접힌 상태로 시작하며 별도 브라우저 저장은 하지 않습니다.
- 하단 버튼은 설명 영역과 분리합니다. 펼쳤을 때 공간이 부족하면 서비스 소개 배너·하단 안내 영역만 스크롤하고 로고·메뉴·접기 버튼은 유지합니다. 본문 폭과 알림의 중앙 위치는 공통 `--sidebar-width`를 따릅니다.
- 하단 접기/펼치기는 별도 박스 배경·테두리·그림자 없이 사이드바 배경과 이어지게 표시합니다. 마우스를 올려도 배경은 같고 아이콘·라벨의 불투명도만 바뀝니다. 44px 높이의 클릭 영역과 기존 키보드 포커스 표시는 유지합니다.
- 760px 이하에서는 기존 상단 메뉴 버튼으로 224px 전체 메뉴를 열고 닫습니다. 하단 데스크톱 토글은 숨기며 페이지 선택·닫기·배경 누르기로 모바일 메뉴를 닫습니다. 모바일 열림과 데스크톱 펼침 상태는 별도입니다.
- 아이콘만 보여도 링크의 접근 가능한 이름을 유지합니다. 토글에는 동작 이름·`aria-expanded`·`aria-controls`가 있고 Enter/Space로 조작할 수 있습니다. 지도 폭 변화는 카카오 `ResizeObserver`의 `relayout`으로 처리합니다.

검증: 공통 메뉴의 직접 진입·페이지 이동 중 상태 유지·재접기·키보드·모바일 메뉴 상태를 자동 테스트 5개로 확인했습니다. Chrome에서 지도 화면의 접기/펼치기와 로고·아이콘 위치 유지, 저장 화면의 펼친 상태 유지 및 재접기, 가이드의 접힌 메뉴 배치를 확인했습니다. 400px 폭의 기기 미리보기에서 모바일 메뉴 열기와 저장 화면 이동을 확인했으나 전체 모바일 높이·실제 모바일/태블릿 기기 검증은 남아 있습니다. 검증용 개발자 도구는 닫고 데스크톱 화면으로 복구했습니다.

## 서비스 소개와 이용 가이드

2026-10-13 이용 가이드 메뉴와 배너가 같은 화면에 연결되던 중복을 해소했습니다.

| 진입 위치                                             | 목적지   | 역할                                                   |
| ----------------------------------------------------- | -------- | ------------------------------------------------------ |
| 주요 메뉴 ‘이용 가이드’, 상단 도움말·하단 데이터 안내 | `/guide` | 지도 조작·업종 선택·결과 해석·저장 등 실제 사용 방법   |
| 펼친 사이드바 배너 ‘PickPlace 소개’                   | `/about` | 서비스 목적·주요 분석 가치·지도에서 시작하는 흐름 소개 |

소개는 [About.tsx](../src/pages/About.tsx)와 [about.css](../src/styles/about.css)로 구성합니다. ‘지도에서 시작하기’는 `/`, ‘이용 방법 보기’는 `/guide`로 연결합니다. 공통 메뉴는 기존 3개를 유지하며 소개는 별도 네 번째 메뉴로 추가하지 않습니다. 상단 경로에는 ‘PickPlace 소개’를 표시하고 공통 상단 바·사이드바 크기와 펼침 상태를 유지합니다. 모바일에서 배너를 누르면 메뉴를 닫습니다.

소개에서 상세 조작 방법이나 점수 범례를 반복하지 않으며 운영 성과·팀 정보·실데이터 연동 완료를 지어내지 않습니다. 데모 수치는 가상 예시임을 안내합니다. 직접 `/about` 진입도 같은 라우트를 사용하며 실제 호스팅은 아래 SPA fallback 설정이 필요합니다. 실행한 내비게이션 검사와 시각 확인 제한은 작업 이력을 따릅니다.

## 실행

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

기본값은 명시적인 **데모 모드**입니다. 서버 없이 일부 예시 지역·업종의 분석 흐름을 확인할 수 있습니다. 첫 화면은 지도 탐색이며 분석 버튼을 누른 후에 결과가 표시됩니다. 점수·통계·AI 문구·시설 마커·경계는 가상 예시입니다. 배경지도는 카카오맵만 사용하며 데모 모드에서도 JavaScript 앱 키와 외부 지도 연결이 필요합니다. 앱 키가 없으면 카카오맵 오류 안내를 표시하고 검색·분석 폼은 유지합니다.

## 지도 설정

카카오맵 설정·우클릭 분석·둘러보기와 장애 대응은 [MAPS.md](MAPS.md)에 있습니다. 2026-10-12 사용자 요청에 따라 지도 선택 메뉴와 다른 지도 렌더러·자동 전환을 제거하고 카카오맵만 사용합니다. 실제 API 모드에서는 조회된 행정동을 FE 지역 목록으로 제한하지 않습니다. 둘러보기는 카카오 배경지도를 확대하며 별도의 점포 검색 API를 호출하지 않습니다.

```dotenv
VITE_KAKAO_MAP_APP_KEY=발급받은_JavaScript_앱_키
```

지도 관련 환경변수는 `VITE_KAKAO_MAP_APP_KEY`만 사용하며 `config.kakaoMapAppKey`로 읽습니다. 이전 공급자·타일 URL·출처·최대 줌 설정은 사용하지 않으므로 로컬·배포 설정에서 정리합니다. 카카오지도 실제 연결에는 JavaScript 키와 서비스 URL 등록이 필요합니다. 키 종류·허용 도메인 오류는 [지도 연결 오류 확인 순서](MAPS.md#연결-오류-확인-순서)를 따릅니다. 키 미설정·SDK/타일 오류에는 `role="alert"` 안내와 ‘카카오지도 다시 시도’를 표시하며 다른 지도로 대체하지 않습니다.

## BE 연결

`.env.local`에 아래를 설정하고 개발 서버를 재시작합니다. 배포 시에는 환경변수를 변경한 뒤 다시 빌드해야 합니다.

```dotenv
VITE_DEMO_MODE=false
VITE_API_BASE_URL=https://your-api.example.com/api
```

`GET /catalog`, `POST /analyses`, `GET /regions/{regionCode}/boundary`의 계약 초안은 [API.md](API.md)에 있습니다. 계약은 아직 BE 확정 전이며, 실제 API 모드에서는 서버 실패 시 데모 데이터로 대체하지 않습니다. 경계는 분석과 별도로 조회하고 실패 시 경계 안내만 표시합니다. 기본 데모에는 실제 경계가 없으며 경계 HTTP 요청도 보내지 않습니다.

2026-10-20 조사에서 경계만 FE 정적 파일로 제공하는 대안도 가능함을 확인했습니다. 후속 사용자 의견에 따라 서울을 포함한 전국 SGIS 읍면동 SHP를 단일 출처로 준비하는 방향입니다. 기존 검증·카카오 렌더러를 재사용하되 공식 자료의 H10 대응·좌표 변환·기준일 확인과 경계 로더/데모 안내 변경이 필요합니다. [정적 경계 제공 제안](MAPS.md#fe-정적-경계-제공-대안)은 미구현이며 현재 실행 방식·환경변수·API 계약은 그대로입니다.

지도 검색 오버레이·지역 선택 동기화·결과 패널 열기/닫기, 좌표 조회·행정동 선택·취소·응답 경합, 카카오 앱 키 미설정·지도 오류/무응답·재시도, SDK 로더, 입력 계층 검증, API 계약·오류, 요청 경합, 결과 지표 전환과 저장 데이터 복원을 테스트합니다. 이용 가이드의 ‘화면 상태 확인’에서 데모 정상/부족/오류 시나리오를 확인할 수 있습니다.

2026-10-08~09 작업 셸에는 `pnpm` 실행 파일이 없어 설치된 의존성과 동일한 package.json 스크립트를 `npm run format`, `npm run format:check`, `npm run test`, `npm run lint`, `npm run build`로 실행했습니다. 의존성·잠금 파일은 변경하지 않았습니다. 최신 휠 보정의 원인·입력 보관 기준·실제 확인 범위는 [확대·축소 끊김 점검](MAPS.md#확대축소-끊김-점검)에 기록했습니다.

2026-10-12 카카오맵 단일화에서 Leaflet 관련 직접 의존성 3개와 전이 의존성을 제거했습니다. 임시 Corepack의 pnpm 10.28.0으로 잠금 파일을 갱신하고 기존 플랫폼 메타데이터·나머지 버전을 보존했습니다. 복사본에서 오프라인 frozen-lockfile 검증을 통과했습니다. 자동 검증은 같은 package.json 스크립트를 npm으로 실행했으며 전체 13개 파일·81개 테스트와 포맷·린트·빌드를 확인했습니다. 최종 재시도 버튼 배치 조정 후 관련 15개 테스트·포맷·린트·빌드를 다시 확인했습니다.

같은 날 독립 경계 연계 추가 후 임시 Corepack의 pnpm 10.28.0으로 `format`·`format:check`·전체 17개 파일 145개 테스트·`lint`·`build`를 통과했습니다. 모의 API/SDK로 좌표 순서·복수 폴리곤/구멍·라벨·출처·재시도·취소·늦은 응답·지역 재선택 시 과거 카드/경계 미복원을 확인했습니다. 실제 BE API가 없어 실데이터 연결은 미검증이며 브라우저 도구가 현재 URL의 Computer Use를 허용하지 않아 이번 실제 화면 검증은 수행하지 못했습니다. 모바일에서 열린 결과 패널 뒤의 선택 경계 출처/재시도 배치는 추가 확인이 필요하며 결과 패널을 닫으면 접근할 수 있습니다.

코드 정리는 `pnpm format`으로 실행합니다. 줄바꿈·들여쓰기·JSX 속성·CSS 선언 기준은 [코드 작성 형식](DEVELOPMENT.md#코드-작성-형식)을 따릅니다.

## 구조

```text
src/components/  공통 UI, 검색, 점수, 차트, 지도, 인사이트
src/pages/       분석, 저장 목록, 이용 가이드, 서비스 소개
src/lib/         설정, HTTP 클라이언트, 검증, 요청 상태, 로컬 저장
src/data/        데모 목록·분석 fixture
src/types/       BE 연동 타입
src/test/        컴포넌트·API·상태 테스트
```

디자인 토큰은 `src/index.css`, 공통 반응형 스타일은 `src/App.css`, 지도 워크스페이스 스타일은 `src/styles/map-workspace.css`에 있습니다. 지도는 별도 청크로 지연 로딩하며 `AreaMap`에서 `KakaoMap`만 렌더링합니다. 지역 조회는 `src/lib/regionLookup.ts`, 지역 검색은 `src/components/MapSearch.tsx`에서 처리합니다. 독립 경계 타입은 `src/types/boundary.ts`, 검증·API·좌표 변환은 `src/lib/regionBoundary.ts`, 취소/재시도 상태는 `src/lib/useRegionBoundary.ts`에 있습니다.

## 정적 배포

`pnpm build`의 `dist/`를 정적 호스팅 또는 Lightsail Nginx에 업로드합니다. BrowserRouter를 사용하므로 모든 FE 경로가 `index.html`로 fallback되어야 합니다. Nginx 예:

```nginx
server {
    listen 80;
    server_name your-domain.example.com;
    root /var/www/pickplace;
    index index.html;
    location / { try_files $uri $uri/ /index.html; }
    # 동일 출처 API를 사용할 경우 FE fallback과 분리합니다.
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

HTTPS·실제 서버 주소·도메인·API 배포는 운영 환경에 맞춰 설정합니다. 이 저장소 변경에는 실제 운영 배포가 포함되지 않습니다.

# 연구용 분기 성장률 연동 계약 초안

기본 상권 분석은 메인 Spring Boot에 요청한다. 로컬 연구 카드는 같은 출처의 격리 Spring 경로를 호출하고 FastAPI 주소와 내부 인증키는 Spring에서 관리한다. 운영 연구 응답 계약은 공동 확인이 필요하다.

## 응답과 표시

기존 `Analysis`의 네 점수는 각각 `Score` 또는 `null`이다. 근거 없는 0점·등급을 만들지 않는다. `trends`가 없으면 빈 배열로 전달하고, 월별 값이 부분적으로 없으면 그 항목을 `null`로 전달한다. FE는 0을 실제 0으로, `null`을 미제공으로 구분하고 없는 달이나 값을 선으로 잇지 않는다. `period`는 기존 `YYYY.MM` 또는 분기 `YYYYQn`을 지원한다.

월별 그래프는 여전히 계약상 점포당 월평균 매출(만원), 일평균 유동인구, 점포 수를 뜻한다. 서울 AI의 기관 제공 분기 집계를 근거 없이 월평균·점포당 값으로 바꾸지 않는다. 월별 자료를 확인하지 못했다면 `trends: []`로 전달한다. 성장률은 따로 연구용 카드에 표시한다.

`researchForecast`는 없거나 null일 수 있다. 있을 때 BE가 AI 응답을 다음과 같이 매핑한다. 두 분기는 별도 API 요청이며, 같은 모델·기준 시점의 결과만 묶는다.

| FE 필드                                  | AI 응답 또는 BE 설정                                                                                                                                   |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mode`                                   | `mode`, 현재 `experimental_research_only`                                                                                                              |
| `method`                                 | 동적 추론이면 `model_inference`                                                                                                                        |
| `basePeriod`                             | `base_period`, 현재 `2026Q2`                                                                                                                           |
| `dataAsOf`                               | `snapshot_available_at` (데이터 확보일)                                                                                                                |
| `modelVersion`                           | `model_sha256` 등 추적 가능한 모델 식별자                                                                                                              |
| `inputValuesVerified`                    | `input_values_verified` 그대로                                                                                                                         |
| `regionScopeVerified`                    | `region_scope_verified` 그대로                                                                                                                         |
| `predictions[].targetPeriod`             | `target_period`                                                                                                                                        |
| `predictions[].status`, `reason`         | `status`, `reason` 그대로                                                                                                                              |
| `predictions[].estimatedYoYGrowth`       | `estimated_yoy_growth` 비율 그대로. `0.05`는 FE에 `+5.0%`로 표시                                                                                       |
| `predictions[].estimateKind`, `warnings` | `estimate_kind`, `warnings` 그대로                                                                                                                     |
| 선택 `predictions[].retrospectiveTest`   | `retrospective_test`의 `target_period`, `rows`, `mae_pp`, `median_absolute_error_pp`를 `targetPeriod`, `rows`, `maePp`, `medianAbsoluteErrorPp`로 변환 |

`retrospectiveTest`는 과거 후향 시험의 평균·중앙 절대오차(퍼센트포인트)이며 미래 신뢰구간이나 정확도가 아니다. AI의 `scope_seen_in_training`은 모델 학습에 해당 조합이 있었는지에 관한 사실일 뿐 코드 대응·지역 적용성 검증이 아니다. `regionScopeVerified=false`, `inputValuesVerified=false`를 임의로 true로 바꾸지 않는다.

`status=unavailable`이면 성장률은 null이고 사유가 있어야 한다. 성공이면 유한한 성장률과 null 사유가 필요하다. 예측 분기 중복, 불가능한 날짜, -100% 미만 성장률은 FE가 거부한다. AI HTTP 200의 `unavailable`은 유효한 부분 결과이며, 401/422/503·네트워크 장애를 0이나 데모로 바꾸지 않는다. 최종 결과의 `source`는 BE가 제공한 출처를 유지하며 연구용 여부는 별도 `mode`로 판단한다.

연구 카드는 입력 분기에서 각 추정 대상 분기로 이어지는 흐름과 전년 동기 대비 성장률을 먼저 표시한다. 연구 한계는 카드에 남기고, 출처·모델·검증 경고·후향 시험의 표본과 절대오차는 펼침 영역에서 확인한다. 화면이 좁으면 흐름이 위에서 아래로 이어진다.

## 아직 필요한 BE 작업

2026-11-16에는 `localhost:5173/__ai-model-test/`에서 브라우저가 별도 Spring 테스트 서버를 호출하고, 기존 `NearTermResearchClient`가 실행 중인 11월 13일 모델의 연구 FastAPI로 요청을 보내는 흐름을 검증했다. 검증한 모델 SHA-256은 `62a6b49736882389379173312fba8d81a284595f8df6098fe0980ac075da9785`다. 일반 상권 분석 요청 및 공식 업종 대응의 운영 경로와는 별개다.

2026-11-16 로컬 미리보기에서 서울 청운효자동 `11110515`·서울 원천 커피·음료 `CS100010`의 연구 API 응답을 기존 연구 카드로 열었다. `2025Q2~2026Q2` 입력으로 얻은 2026Q4 전년 동기 대비 추정은 −9.2136%이며 Safari에서는 −9.2%로 표시된다. 서울특별시·서울신용보증재단의 [추정매출](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do)과 [점포](https://data.seoul.go.kr/dataList/OA-22172/S/1/datasetView.do) 원천은 출처표시 조건의 공공누리 제1유형이다.

청운효자동의 H10 `1111051500`과 서울 원천 지역 코드는 기준정보에서 대응한다. [서울 분류표](https://golmok.seoul.go.kr/images/100_v3.pdf)의 `CS100010`은 커피 전문점(`56221`) 범위다. 같은 지역의 [소진공 9월 원본](https://www.data.go.kr/data/15083033/fileData.do)에서 카페 `I21201` 80곳에는 커피 전문점 75곳과 기타 비알코올 음료점(`56229`) 5곳이 포함된다. 분류 범위가 다르므로 서울 원천 업종으로만 로컬 검증했다. 공개 분석의 업종 대응 및 운영용 입력 승인과 실제 예측 정확도 검증은 남아 있다.

- 카카오 H10과 서울 `seoul-adstrd` 8자리의 공식 대응·기준일을 확인한다. 코드 자르기와 이름 추정을 사용하지 않는다.
- AI에 동일 지역·업종의 `2025Q2~2026Q2` 연속 5분기 이력과 실제 데이터 취득일을 전달한다. AI 서버는 현재 기준 분기·지원 대상이 고정되어 있다.
- PR #18의 실제 API 모드에서는 BE의 자치구·행정동·지원 업종 개별 API를 사용한다. `CS...` 업종은 데모의 `coffee` 등 별칭과 다르며, 목록의 8자리와 H10의 공식 대응 및 지도 이동은 별도 확인이 필요하다.
- AI 연결 실패와 데이터 부족, 부분 결과, 형식 오류를 구분하고 모델키는 BE 환경에서만 보관한다. 일반 분석의 승인 데이터 기준 통합 검증과 운영 배포는 남아 있다.

## 상권 분석 화면의 로컬 참고 결과

PickPlace 루트의 `test-integration.sh`가 실행한 로컬 FE는 서울 행정동과 카페·김밥/만두/분식·빵/도넛 중 하나를 분석할 때 원천 범위를 확인한다.

- 일반 성장률이 비어 있으면 기존 매출 성장률 카드 안에서 2026년 2분기 자료로 추정한 4분기 전년 동기 대비 변화율을 조회해 연구용으로 표시한다. 일반 성장률을 받으면 우선 표시한다.
- 업종 적합도 카드에는 FastAPI 참조표에서 반환한 점포당 주민 수, 1㎢당 점포 수와 자료 기준일을 표시한다. 비교표는 같은 기준일의 주민등록인구와 행정동 경계, 같은 분기의 서울 점포 수를 사용한다. 지수 점수는 별도의 승인 입력으로 계산한다.
- 연구용 추정과 비교 지표는 서울 원천 세부 업종 기준을 표시한다. 대응이나 이력이 없으면 일반 분석과 기본 통계는 계속 볼 수 있다. 지역·업종이 바뀌면 진행 중인 로컬 요청을 취소한다.

로컬 조회 경로는 `POST /__ai-model-api/research/forecast`와 `GET /__ai-model-api/fit-reference`이며, 두 요청은 현재 분석의 `regionCode`·`industryCode`를 쿼리로 보낸다. 일반 분석 v2의 `analysisScope`는 지표 영역과 PDF 보고서에 서울 원천 업종 기준을 표시한다. 결과 패널에서 내려받은 PDF에는 현재 조회된 로컬 연구용 추정과 적합도 참고 지표를 담는다. 저장 목록의 PDF는 브라우저에 저장된 분석만 사용한다.

### 일반 분석과 적합도 비교의 미제공 사유

- Spring 일반 분석의 `mapping_unverified`는 지역·업종 대응 승인 미확인, `region_not_supported`는 서울 외 일반 AI 미지원으로 표시한다. 일반 분석 상태는 기본 통계와 로컬 연구용 추정을 가리지 않는다.
- 로컬 적합도 비교 조회는 FastAPI에서 해당 조합이 참조표에 없다고 응답하고 동일 기준일의 경계 검증에서 양방향 겹침 기준 미달이 확인된 경우 `404 FIT_REFERENCE_BOUNDARY_UNVERIFIED`를 반환한다. 화면은 적합도 카드에서 경계 검증 미달을 표시한다. 다른 자료 부족은 `FIT_REFERENCE_NOT_AVAILABLE`로 처리한다.

### 일반 AI 위험 지수의 로컬 시험 범위

- 고척2동의 서비스 H10 `1153073000`과 서울 원천 행정동 코드 `11530730`을 대조했다. 2026년 9월 소진공 카페 `I21201` 21곳 중 19곳은 커피 전문점(`56221`)이다. BE의 2026Q2 위험도 입력 확인표에도 이 조합이 포함돼 있어 로컬 시험에서 서울 원천 커피 전문점 `CS100010` 기준의 부분 대응으로 다룬다.
- Spring은 시험용으로 등록된 지역·업종 대응과 승인된 분기별 입력을 확인한 뒤 서울 원천 코드와 관측 이력을 FastAPI로 보낸다. 고척2동의 전년 동기 추정매출은 218,115,170원이며 2026Q2 추정매출은 252,144,448원, 점포는 33곳, 폐업은 0곳이다. 이 입력으로 계산한 위험 지수는 0.0점이다.
- 신촌동 카페는 원천 자료와 지역 코드 대응을 확인했으며 BE의 카페 위험도 입력 확인표에는 포함되지 않는다. 일반 위험 지수 제공은 지역·업종 대응과 분기별 입력 사용 승인을 확인한 뒤 검토한다. 로컬 적합도 비교는 별도 경계 검증 기준을 적용한다. [BE와 합의한 분석 기준](https://github.com/teojabi-groundbreakers/pickplace-backend/issues/36)

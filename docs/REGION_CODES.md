# 지역코드 기준

확인일: 2026-10-09. 현재 FE 구현과 확인된 출처를 설명하는 문서입니다. 실제 BE의 코드 체계·변환 계약은 아직 확정하지 않았습니다.

PickPlace의 위치 분석 단위는 **행정동**입니다. 지도에서 조회한 지역은 카카오가 반환한 행정동(`region_type: H`)의 원본 코드를 사용합니다. FE가 지역 이름·좌표를 보고 코드를 새로 만들거나 자체 지역 목록에 있어야만 분석을 허용하지 않습니다.

## 현재 코드의 출처와 형식

| 사용 위치      | 기준 / 출처                                                   | 현재 형식과 예시                               | 확인 상태                                |
| -------------- | ------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------- |
| 데모 시·도     | `src/data/demo.ts`의 `cities[].code`                          | 문자열 2자리: 서울특별시 `11`, 부산광역시 `26` | UI 예시, 공식 배포본·기준일 기록 없음    |
| 데모 시·군·구  | 같은 파일의 `districts[].code`                                | 문자열 5자리: 마포구 `11440`                   | UI 예시                                  |
| 데모 행정동    | 같은 파일의 `neighborhoods[].code`                            | 문자열 8자리: 서교동 `11440660`                | 일부 값 불일치, 전체 공식 검증 전        |
| 지도 좌표 조회 | 카카오 지도 SDK `services.Geocoder.coord2RegionCode`의 H 결과 | 문자열 10자리: 서교동 `1144066000`             | 실제 조회 및 FE 형식 검사 확인           |
| API 지역 목록  | BE의 `GET /catalog`                                           | BE가 제공한 코드 문자열을 보존                 | 코드 체계·자릿수·기준일은 BE와 확정 전   |
| 분석 요청      | 선택한 목록 코드 또는 지도 조회 H 코드                        | `POST /analyses`의 `regionCode` 문자열         | 지도 조회 10자리 코드의 BE 수용은 미검증 |

데모 값은 소스에 직접 작성된 예시입니다. 원본 공식 코드 파일을 가져와 검증한 전국 목록이 아니므로, 모양이 행정코드와 같다고 해서 이름·코드의 대응이나 현재 유효성이 보장되지 않습니다. 실제 API 모드의 지역 목록은 서버가 제공합니다.

현재 카탈로그 검증은 코드가 비어 있지 않은 문자열인지 확인합니다. 2·5·8자리를 모든 BE 응답에 강제하는 구현은 아닙니다. 상위 시·도·시·군·구는 카탈로그의 중첩 관계로 찾으며 지도 조회 코드의 앞자리를 잘라 부모 항목을 추정하지 않습니다.

## 행정동과 법정동 구분

카카오는 같은 좌표에 대해 행정동 `H`와 법정동 `B`를 구분해서 반환합니다. 분석에는 `H`만 사용하며, `H`가 없을 때 `B`나 가장 가까운 중심 마커로 대체하지 않습니다. 코드 길이나 지역 이름만으로 두 종류를 판별하지 않습니다. [카카오 좌표→행정구역 응답 명세](https://developers.kakao.com/docs/ko/local/dev-guide#coord-to-district)

카카오 공식 예제에서도 같은 삼평동 이름에 법정동 `4113510900`과 행정동 `4113565500`이 따로 표시됩니다. 이 값은 **공식 문서 예제**이며 현재 서비스 지역의 최신 코드 목록을 검증했다는 의미는 아닙니다. [카카오 공식 응답 예제](https://developers.kakao.com/docs/ko/local/dev-guide#coord-to-district)

## 8자리와 10자리의 관계

현재 데모의 계층 구조는 시·도 2자리 + 시·군·구 3자리 + 읍·면·동 3자리 형태입니다. 서교동 예시를 풀면 다음과 같습니다.

| 부분  | 의미       | 누적 코드  |
| ----- | ---------- | ---------- |
| `11`  | 서울특별시 | `11`       |
| `440` | 마포구     | `11440`    |
| `660` | 서교동     | `11440660` |

현재 데모 어댑터는 8자리 예시 코드 뒤에 `00`을 붙인 값과 조회된 10자리 코드를 비교합니다. 예를 들어 데모 `11440660`과 조회 `1144066000`이 유일하게 일치하면 같은 예시 결과를 사용합니다. 이 규칙은 **데모 fixture를 찾는 구현 규칙**이며, 서로 다른 기관·통계 데이터의 코드를 변환하는 범용 규칙이 아닙니다.

- `findSupportedRegion()`은 데모 분석에서만 사용합니다. 같은 코드가 여러 예시 지역과 매칭되면 선택하지 않습니다.
- 실제 API 요청에서 조회 코드를 8자리로 자르거나, 이름이 비슷한 다른 코드로 치환하지 않습니다.
- 법정동 코드·통계용 행정구역분류코드 등 다른 출처의 코드를 연결하려면 원본 코드 체계·기준일·공식 매핑을 먼저 확인합니다. 자릿수가 같다는 이유로 동일한 식별자로 취급하지 않습니다.

## 지도 조회와 백엔드 전달 기준

1. 지도 클릭 좌표 `[위도, 경도]`를 카카오 SDK에 **경도, 위도** 순서로 전달합니다. 입력 좌표계는 SDK 기본값 WGS84입니다. [카카오 SDK 조회 메서드](https://apis.map.kakao.com/web/documentation/#services_Geocoder_coord2RegionCode)
2. 응답 중 `region_type === 'H'`를 선택하고 코드가 숫자 10자리이며 지역명이 있는지 검사합니다. 이 형식 검사만으로 분석 데이터 존재 여부가 보장되지는 않습니다.
3. 조회된 코드와 사용자가 고른 업종을 기존 분석 API로 요청합니다. FE 카탈로그 포함 여부로 차단하지 않습니다.

```json
{ "regionCode": "1144066000", "industryCode": "coffee" }
```

4. BE는 코드 유효성·지원 지역·표본 부족 여부를 판단해야 합니다. 내부 집계 코드로 변환하더라도 응답 `request.regionCode`에는 원본 요청을 보존하는 것이 현재 FE 계약 초안입니다. FE는 요청과 다른 코드의 결과를 거부합니다.
5. 상단 재분석·분석 저장·재열기에도 원본 요청 코드를 유지합니다. 둘러보기는 분석 API를 호출하지 않습니다.

카카오 조회는 원본 10자리 H 코드를 사용하도록 구현했지만, 실제 BE의 수용·변환·전국 데이터 제공 범위는 아직 확인하지 않았습니다. 요청·응답 필드는 [API 계약 초안](API.md#post-analyses), 화면 흐름은 [지도 분석·둘러보기](MAPS.md#지도-위치의-행정동-조회와-분석둘러보기)를 참조합니다.

## 공식 기준 자료와 갱신 방법

행정동 전체 코드와 법정동·행정동 매핑의 확인 경로는 [행정표준코드관리시스템 FAQ](https://www.code.go.kr/qna/faqL.do)가 안내하는 행정안전부 자료입니다. [행정안전부 주민등록·인감 게시판](https://www.mois.go.kr/frt/bbs/type001/commonSelectBoardList.do?bbsId=BBSMSTR_000000000052)에서 최신 주민등록주소코드 변경내역과 첨부파일을 확인합니다. 이번 작업에서는 확인 경로를 조사했으며 최신 첨부 코드 전체를 내려받아 대조하지 않았습니다.

운영 데이터 연계 전에는 BE·데이터 담당자가 다음 기준을 확정하고 문서에 남깁니다.

- 원본 제공 기관·자료명·다운로드 URL, 적용 기준일과 수집일
- 행정동/법정동 등 코드 종류, 자릿수, 사용 중·폐지 코드 처리 기준
- 카카오 H 코드와 매출·인구·점포 데이터 집계 코드 사이의 공식 대응 관계
- 분동·통합·명칭 변경 시 과거 기간의 통계와 저장된 분석을 연결하는 기준

행정구역 변경 시 이름으로 자동 연결하거나 과거 통계를 현재 코드에 임의 합산하지 않습니다. 같은 체계·기준 시점에 대응하는 코드인지 확인한 뒤 별도 변경으로 적용합니다.

## 알려진 제한과 미완료 사항

| 지역       | 현재 데모 코드 | 실제 카카오 H 조회 기록 | 후속 작업                                                                                                                 |
| ---------- | -------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 연남동     | `11440590`     | `1144071000`            | [이슈 #5](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/5)에서 공식 코드 검증·저장 데이터 영향 확인 |
| 성수2가1동 | `11200690`     | `1120067000`            | [이슈 #6](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/6)에서 공식 코드 검증·기본 요청 영향 확인   |

위 불일치는 접미사 `00`만으로 해결되지 않습니다. 실제 조회 기록은 코드 원본 배포본 전체를 검증한 결과와 구분합니다. 이 문서 작업에서는 소스의 데모 코드를 교정하지 않았으며, 나머지 예시 지역도 공식 기준과의 일괄 대조가 필요합니다. 실제 API 모드의 분석 요청은 이러한 FE 데모 값과 무관하게 조회한 H 코드를 전달합니다.

# 지도 우선 흐름과 지도 공급자

## 화면 흐름

1. 첫 화면의 주 콘텐츠는 화면 높이를 채우는 지도입니다. 큰 소개 제목·독립된 검색 카드 대신 상단 검색 오버레이를 표시합니다.
2. 상단에서 시·군·구/행정동 이름을 검색하거나 지도 마커·‘표시된 행정동’ 목록으로 지역을 고릅니다. 조건 버튼에서 계층별 지역과 업종을 선택할 수 있습니다. 선택은 서로 동기화됩니다.
3. ‘상권 분석하기’를 누르면 지도 위 결과 패널에 점수·차트·진단을 표시합니다. 데스크톱은 오른쪽, 좁은 화면은 하단 패널이며 닫기·다시 열기·저장·다운로드를 지원합니다.
4. 지도 우클릭 또는 ‘중심 위치 조회’로 해당 좌표의 행정동을 확인합니다. 카드에서 업종을 고른 뒤 ‘이 지역 분석’으로 분석을 요청하거나 ‘이 지역 둘러보기’로 클릭 위치를 확대합니다. 조회 시작 시 결과 패널을 접어 카드를 표시합니다.
5. 검색 조건을 바꾸면 지도에서 이전 분석의 시설·경계를 숨깁니다. 이전 결과에는 재분석 안내를 표시합니다.

단순 클릭 위치를 임의의 행정동으로 간주하지 않습니다. 중심 마커는 분석 목록의 지역 선택이며, 임의 지점은 아래 실제 좌표 조회 서비스를 사용합니다.

## 지원하는 지도

| 모드        | 표시 방식                                               | 필요한 설정                            |
| ----------- | ------------------------------------------------------- | -------------------------------------- |
| `kakao`     | 카카오지도 Web SDK, 행정동 선택·경계·시설 마커          | JavaScript 앱 키 및 서비스 URL 등록    |
| `custom`    | 허가받은 별도 타일 서버/자체 호스팅                     | Web Mercator XYZ 래스터 URL, 출처 표기 |
| `osm`       | OSM 공용 표준 타일, Leaflet                             | 키 없음, OSM 사용 정책 준수            |
| `schematic` | 외부 배경 요청 없는 기본 위치도, Leaflet                | 키·외부 지도 서버 없음                 |
| `auto`      | 설정된 카카오 → 설정된 별도 타일 → OSM 순서로 초기 선택 | 개발 기본값                            |

기본 위치도는 실제 위경도에 행정동 중심·제공된 경계·시설을 올립니다. **실제 도로나 지형을 표시하는 지도는 아닙니다.** OSM 타일을 다운로드하거나 저장해서 오프라인으로 제공하는 방식이 아닙니다.

카카오지도는 OSM 공용 타일 URL을 사용하지 않는 별도 SDK 경로입니다. 다른 OSM 기반 타일 공급자로 옮기는 경우에는 공용 서버 의존성은 줄어도 데이터 라이선스 의무까지 없어지는 것은 아니므로, 공급자별 조건을 확인해야 합니다.

## 카카오지도 사용

`.env.local` 예시:

```dotenv
VITE_MAP_PROVIDER=kakao
VITE_KAKAO_MAP_APP_KEY=발급받은_JavaScript_앱_키
```

[Kakao 지도 Web API 가이드](https://apis.map.kakao.com/web/guide/)에 따라 앱을 준비하고 개발/운영 서비스 URL을 등록합니다. 브라우저용 JavaScript 키를 사용하며 REST API 키나 관리자 키를 넣지 않습니다. VITE 환경변수는 번들에 노출되므로 허용 도메인 제한을 설정합니다. 계정 생성·약관 동의·앱 키 발급은 이 작업에서 수행하지 않았습니다.

### 연결 오류 확인 순서

1. `.env` 또는 `.env.local`의 `VITE_KAKAO_MAP_APP_KEY`가 해당 앱의 **JavaScript 키**인지 확인합니다. 실제 키는 로그·문서·이슈에 남기지 않습니다.
2. 해당 JavaScript 키의 허용 도메인에 현재 브라우저의 출처를 등록합니다. 로컬 개발의 `http://localhost:5173`과 `http://127.0.0.1:5173`은 서로 다른 출처입니다. 포트나 프로토콜이 달라지면 해당 주소도 확인합니다.
3. 앱의 카카오맵 사용 설정을 확인합니다. 설정 경로와 조건은 [카카오맵 공식 안내](https://developers.kakao.com/docs/ko/kakaomap/common)를 기준으로 확인합니다.
4. 환경변수 변경 후 개발 서버에 새 값이 반영됐는지 확인하고 브라우저를 새로고침합니다. 배포 환경은 다시 빌드합니다.
5. 브라우저 네트워크에서 SDK 응답, 지도 이미지 로딩, 실제 지도 표시를 각각 확인합니다. SDK HTTP 200만으로 지도 표시 완료를 판단하지 않습니다.

| 실제 응답                              | 의미 및 조치                                                                 |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| HTTP 401, `appKeyType is REST_API_KEY` | Web SDK에 REST API 키를 전달한 상태. JavaScript 키로 교체                    |
| HTTP 401, `domain mismatched!`         | 현재 출처가 해당 키의 허용 도메인과 불일치. 현재 프로토콜·호스트·포트를 등록 |
| SDK 성공 후 배경 지도 실패             | 타일 요청·앱 사용 설정·브라우저 오류를 별도로 확인                           |

2026-10-08 로컬 점검에서 REST API 키 오류와 키 교체 후 허용 도메인 불일치를 순서대로 확인했습니다. 후속 제스처 작업 시 두 로컬 출처의 SDK 응답이 HTTP 200으로 바뀌었고, Chrome의 `localhost:5173`에서 실제 카카오 도로지도 표시와 우클릭·중심 위치의 서교동 행정동 조회 성공을 확인했습니다. 키 값은 기록하지 않았으며 `.env`는 Git 제외 대상임을 확인했습니다. `127.0.0.1:5173`의 실제 렌더링·운영 도메인 연결은 별도로 확인해야 합니다.

### 카카오 지도 조작

화면을 채우는 지도를 바로 탐색하도록 SDK 생성 옵션에 `draggable: true`, `scrollwheel: true`, `disableDoubleClick: false`, `disableDoubleClickZoom: false`를 적용합니다. 드래그·더블클릭·모바일 터치는 SDK 기본 동작을 사용합니다. `scrollwheel`은 SDK의 터치 확대·축소도 제어하므로 활성화 상태를 유지합니다.

사용자가 트랙패드 스크롤이 페이지 입력으로 처리된다고 보고해 `src/lib/kakaoMapWheel.ts`에서 카카오 지도 컨테이너에만 네이티브 `wheel` 리스너를 추가했습니다. `{ capture: true, passive: false }`로 기본 스크롤을 취소하고 SDK 내부로 같은 이벤트가 전달되지 않게 합니다. 공개 API `getProjection().coordsFromContainerPoint()`와 `setLevel(level, { anchor })`로 포인터 위치를 기준으로 확대·축소하며 SDK 비공개 함수를 호출하지 않습니다.

- 픽셀·줄·페이지 단위를 환산하고 작은 세로 입력도 누적합니다. 누적 40px마다 한 단계, 최소 160ms 간격으로 확대·축소해 관성 입력의 속도를 제한합니다. 방향 전환 또는 180ms 초과 입력 중단 시 누적값을 초기화합니다.
- 도로지도 배율 1~14에서 제한합니다. 배율 끝과 수평 위주 입력에서도 페이지 스크롤은 취소하되 수평 입력으로 확대하지 않습니다. 지도 안의 Ctrl+휠도 지도 입력으로 처리합니다.
- 검색 오버레이·결과 패널·조회 카드는 지도 컨테이너의 형제 요소이므로 이 리스너의 대상이 아닙니다. 그 안의 목록 스크롤은 유지합니다. 지도 안의 행정동·시설 마커 위 휠은 지도 확대·축소로 처리하고 버튼 클릭은 그대로 유지합니다.
- 언마운트 시 네이티브 리스너를 제거합니다. 더블클릭·우클릭·터치 이벤트는 이 보정 처리의 대상이 아닙니다.

공식 배포 SDK `4.5.28`에서 `wheelDelta` 없는 1px 미만 `deltaY` 입력을 누적하지 않는 경로를 확인했습니다. 사용자 환경의 원시 이벤트를 수집하지 않아 해당 분기가 현장 문제의 단일 원인인지는 확정하지 않았습니다. SDK 옵션만 재설정하는 대신 표준 `wheel` 입력과 스크롤 취소를 직접 처리합니다.

| 입력                               | 동작                    | 2026-10-08 확인 상태                                       |
| ---------------------------------- | ----------------------- | ---------------------------------------------------------- |
| 왼쪽 버튼 드래그                   | 지도 이동               | 사용자 정상 동작 확인                                      |
| 마우스 휠·트랙패드 세로 스크롤     | 지도 확대·축소          | 보정 및 모의 이벤트 테스트 통과, 실제 트랙패드 재확인 대기 |
| 더블클릭                           | 클릭 지점 확대          | 사용자 정상 동작 확인                                      |
| 오른쪽 버튼 클릭                   | 클릭 좌표의 행정동 조회 | 실제 서교동 H 코드 `1144066000` 조회 성공                  |
| 한 손가락 이동·두 손가락 확대/축소 | SDK 터치 탐색           | 설정 적용, 실제 모바일 기기 미검증                         |

확대·축소 버튼과 ‘중심 위치 조회’도 유지합니다. 조작 안내는 이용 가이드에 제공합니다.

이전 자동 조작에서 축척 `100m` → `250m` 변화만 확인한 기록은 실제 트랙패드 입력과 페이지 스크롤 차단의 검증으로 충분하지 않았습니다. 사용자 보고에 따라 휠 정상 동작 판정을 철회했습니다. 이번 수정 후 브라우저 자동 검증은 두 차례 `Sky Computer Use native pipe startup failed`로 연결되지 않아 실제 트랙패드는 재검증하지 못했습니다.

수동 확인은 지도 빈 영역에서 두 손가락 세로 스크롤 양방향의 축척 변화·포인터 기준 위치 유지·페이지 고정, 지도 마커 위 휠, 검색 목록·결과 패널 내부 스크롤을 구분해 진행합니다. 드래그·더블클릭·우클릭·모바일 터치도 수정 후 회귀 확인 대상입니다. 미세 이동 후 타임아웃 오탐 수정은 아래 별도 PR #4에 있으며 이 feature 브랜치에는 포함하지 않습니다.

근거: [카카오 Map 생성 옵션·setLevel·MapProjection 공식 문서](https://apis.map.kakao.com/web/documentation/), [공식 배포 SDK 4.5.28](https://t1.kakaocdn.net/mapjsapi/js/main/4.5.28/kakao.js), [표준 wheel 이벤트·스크롤 취소](https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event). 확인일은 2026-10-08입니다.

### 지도 위치의 행정동 조회와 분석·둘러보기

2026-10-09 사용자 사양 변경에 따라 기존 ‘이 지역 선택’과 FE 지역 목록 포함 여부 검사를 제거했습니다. [이슈 #1](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/1)의 기존 지도 탐색 목적을 보완하며 `feature/1-map-workspace`·Draft PR #3에서 진행합니다.

- Leaflet `contextmenu`, 카카오 `rightclick`에서 실제 위경도를 받아 공식 `services.Geocoder.coord2RegionCode`에 **경도, 위도** 순서로 전달합니다. SDK는 `libraries=services`를 로드합니다. 행정동(`region_type: H`)의 유효한 10자리 코드와 이름을 사용하며 법정동·가장 가까운 마커로 대체하지 않습니다.
- 조회 카드에는 행정동 이름·코드·좌표, ‘분석할 업종’ 드롭다운, ‘이 지역 분석’·‘이 지역 둘러보기’를 표시합니다. 업종은 현재 검색 조건과 동기화하고 대분류별 옵션 그룹으로 표시합니다. 사용자 표현의 ‘데이터’는 현재 분석 계약에 맞춰 업종으로 해석했습니다. 지표 선택을 뜻하는지는 추가 답변 전이며 [API 초안](API.md)에 구분했습니다.
- **이 지역 분석**: FE 지역 카탈로그에 없는 행정동도 조회한 10자리 H 코드와 선택 업종을 기존 `POST /analyses`로 요청합니다. 기존 ‘상권 분석하기’와 `useAnalysis.run`·로딩·오류·데이터 부족·재시도·결과 패널을 공유합니다. 코드·이름·클릭 좌표는 현재 선택 상태로 유지하며 지역 목록에 삽입하거나 별도의 지역 허용 목록으로 저장하지 않습니다. 상단 재분석과 분석 저장 후 재열기에도 원본 요청 코드를 보존합니다.
- 업종 미선택·목록 조회 실패·분석 진행 중에는 새 분석을 막습니다. 분석 지원 여부·표본 부족 여부는 실제 API 모드에서 서버 응답으로 처리하며 오류를 데모 결과로 대체하지 않습니다. 실제 BE의 10자리 H 코드 수용·전국 데이터 가용성은 미검증입니다.
- **이 지역 둘러보기**: 분석 API를 호출하거나 분석 조건의 지역을 바꾸지 않습니다. 클릭 좌표로 이동해 카카오는 현재 레벨과 3 중 더 확대된 배율, Leaflet은 현재 줌과 17 중 더 확대된 배율(공급자 최대 줌 이하)을 사용합니다. 조회 카드·결과 패널을 접고 둘러보는 지역명을 지도에 표시합니다. 이전 분석의 경계·시설 마커는 숨깁니다. 업종만 바꿀 때는 둘러보는 위치·배율을 유지하고 지역 변경·분석 실행 시 탐색 상태를 해제합니다.
- 점포명은 확대된 **배경지도 자체의 POI 표시**를 사용합니다. 점포 검색 API·전체 점포 목록·실시간 영업 현황을 제공하는 구현은 아닙니다. 카카오 외 타일의 표시 정보는 제공자에 따라 다르며 기본 위치도에서는 실제 점포를 볼 수 없다고 안내합니다.
- 데모 모드에서는 유일하게 일치하는 예시 지역의 8자리/10자리 코드만 대응해 예시 결과를 만들고 요청 코드는 보존합니다. 예시가 없으면 ‘데모 분석 데이터가 없습니다’라는 데이터 부족 상태를 표시하며 다른 지역 결과를 대신 보여주지 않습니다. 실제 조회 행정동을 분석하는 API 모드는 FE 예시 목록과 무관합니다.
- 알려진 데모 코드 불일치: 연남동은 [이슈 #5](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/5), 성수2가1동은 [이슈 #6](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/6)에서 별도로 검증합니다. 이번 UI 변경에서는 코드 데이터를 교정하거나 이름으로 우회하지 않았습니다.
- 모바일·키보드에는 ‘중심 위치 조회’ 버튼을 제공합니다. 배경 지도 공급자와 행정구역 조회 서비스를 분리하므로 `custom`·`osm`·`schematic`에서도 사용자가 위치 조회를 실행하면 카카오 SDK 요청이 발생할 수 있습니다.
- 미설정·오류·빈 결과·서비스 누락·10초 무응답을 안내합니다. 다음 위치 조회·닫기·언마운트 시 이전 요청을 취소하고 늦은 응답을 무시합니다. 공유 SDK 로더 자체는 취소하지 않습니다. 지역 검색과 수동 조건 선택은 계속 사용할 수 있습니다.

검증: 2026-10-09 전체 11개 파일·58개 테스트에서 목록 밖 행정동의 POST 본문·업종 동기화·재분석·저장/재열기·오류/재시도·데이터 부족·둘러보기 무호출·뷰포트 확대·데모 제한·기존 휠 동작을 모의 검증했습니다. Chrome `localhost:5173`에서 실제 카카오 우클릭 응답·업종 드롭다운·두 버튼 배치, 둘러보기 축척 `250m` → `50m`와 점포명 표시, 미용실 선택의 상단 동기화 및 예시 없는 지역의 데모 데이터 부족 안내를 확인했습니다. 실제 BE 연결·모바일 시각 검증·수정 후 실제 트랙패드 검증은 별도입니다.

근거: [카카오 지도 공개 API 문서](https://apis.map.kakao.com/web/documentation/), [행정동 조회 예제](https://apis.map.kakao.com/web/sample/coord2addr/), [Leaflet 뷰포트 API 문서](https://leafletjs.com/reference.html#map-setview). 확인일은 2026-10-09입니다.

## 별도 타일/자체 호스팅

```dotenv
VITE_MAP_PROVIDER=custom
VITE_MAP_TILE_URL=/tiles/{z}/{x}/{y}.png
VITE_MAP_ATTRIBUTION=사용 허가를 받은 제공자의 필수 출처 표기
VITE_MAP_MAX_ZOOM=19
```

256px Web Mercator XYZ 래스터 타일을 사용합니다. HTTPS URL 또는 동일 출처 `/` 경로와 `{z}`, `{x}`, `{y}`가 필요하며, URL과 출처 표기가 모두 있어야 활성화됩니다. 타일 크기·좌표계가 다른 서비스는 어댑터가 추가로 필요합니다. Kakao/네이버의 비공개 타일 URL을 추출해 연결하지 않습니다. 라이선스·출처·캐시 조건은 사용 권한을 확보한 공급자 기준으로 설정합니다.

## 장애 대응

- Leaflet 타일: 한 로드에서 3회 이상 실패하거나 성공 타일 없이 실패한 경우, 또는 12초간 로딩이 완료되지 않으면 공급자를 전환합니다.
- 카카오: SDK 로드 실패/10초 초과, 지도 생성 실패, 타일 이미지 반복 오류/12초 초과에 대응합니다.
- 실패한 공급자는 제외하고 설정된 카카오/별도 타일을 시도한 뒤 기본 위치도로 전환합니다. **OSM은 다른 공급자의 암묵적인 대체 서비스로 사용하지 않습니다.**
- `kakao`/`custom`을 명시했는데 설정이 빠진 경우에도 OSM을 호출하지 않고 기본 위치도로 표시합니다.
- 복구 중 선택 지역·업종과 분석 요청 상태를 유지하며, 전환 알림과 ‘다시 시도’를 제공합니다.
- 사용자가 ‘기본 위치도’를 선택하면 배경 타일·배경 표시용 카카오 SDK를 요청하지 않습니다. 단, 별도로 위치 조회를 실행하면 카카오 조회 SDK를 요청합니다. 이미 로드된 타일이나 SDK는 재선택 시 브라우저 캐시/런타임에 남을 수 있습니다.

2026-10-08 이벤트 모의 테스트에서 정상 `tilesloaded` 이후 타일 추가 로드 없는 `bounds_changed`에도 12초 뒤 실패하는 기존 카카오 타임아웃 오탐을 재현했습니다. [이슈 #2](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/2)로 분리했으며 지도 화면 개편 브랜치에는 해당 수정을 섞지 않았습니다. 공식 문서상 타일 추가 로드 없는 미세 이동에서는 `tilesloaded`가 발생하지 않습니다. `fix/2-kakao-tile-timeout`의 별도 worktree에서 수정·검증하고 [Draft PR #4](https://github.com/teojabi-groundbreakers/pickplace-frontend/pull/4)를 생성했으며 아직 이 feature 브랜치에 반영하거나 develop에 병합하지 않았습니다. 수정 브랜치의 전체 테스트 33개·포맷·린트·빌드는 통과했습니다.

환경변수 변경 후 개발 서버를 재시작하고 운영 배포는 다시 빌드합니다. 지도 선택 메뉴에서도 사용할 수 있는 공급자를 전환할 수 있습니다.

## OSM 공용 타일 관련 근거

[OSMF Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/)는 공용 타일의 가용성/SLA를 보장하지 않으며 출처 표기와 캐시 준수 등을 요구합니다. 공용 타일의 일괄 다운로드 및 오프라인 타일 제공은 금지합니다. 따라서 운영 환경에서는 `kakao` 또는 허가받은 `custom` 공급자를 명시하고, 기본 위치도를 최종 대안으로 두는 구성을 권장합니다.

테스트는 지도·검색 조건 동기화, 타일 오류/무응답, 복구 순서, SDK 실패·재시도·타임아웃을 모의 환경에서 검증합니다. 실제 공급자 연결과 화면 배치는 운영 키 및 브라우저 환경에서 별도 확인이 필요합니다.

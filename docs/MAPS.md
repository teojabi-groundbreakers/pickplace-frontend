# 지도 우선 흐름과 카카오맵

## 화면 흐름

1. 첫 화면의 주 콘텐츠는 화면 높이를 채우는 지도입니다. 큰 소개 제목·독립된 검색 카드 대신 상단 검색 오버레이를 표시합니다.
2. 상단에서 시·군·구/행정동 이름을 검색하거나 지도 마커·‘표시된 행정동’ 목록으로 지역을 고릅니다. 조건 버튼에서 계층별 지역과 업종을 선택할 수 있습니다. 선택은 서로 동기화됩니다.
3. ‘상권 분석하기’를 누르면 지도 위 결과 패널에 점수·차트·진단을 표시합니다. 데스크톱은 오른쪽, 좁은 화면은 하단 패널이며 닫기·다시 열기·저장·다운로드를 지원합니다.
4. 지도 우클릭 또는 ‘중심 위치 조회’로 해당 좌표의 행정동을 확인합니다. 카드에서 업종을 고른 뒤 ‘이 지역 분석’으로 분석을 요청하거나 ‘이 지역 둘러보기’로 클릭 위치를 확대합니다. 조회 시작 시 결과 패널을 접어 카드를 표시합니다.
5. 검색 조건을 바꾸면 지도에서 이전 분석의 시설·경계를 숨깁니다. 이전 결과에는 재분석 안내를 표시합니다.

단순 클릭 위치를 임의의 행정동으로 간주하지 않습니다. 중심 마커는 분석 목록의 지역 선택이며, 임의 지점은 아래 실제 좌표 조회 서비스를 사용합니다.

지도 화면에도 [공통 사이드바](FRONTEND.md#공통-사이드바)를 사용합니다. 기본 76px에서 하단 `>`로 펼치며 다른 페이지로 이동해도 메뉴 위치·펼침 상태를 유지합니다. 지도 전용 사이드바 스타일은 두지 않고 지도 본문·검색 오버레이 배치만 이 문서에서 관리합니다.

## 카카오맵 단일 사용

2026-10-12 사용자가 카카오맵의 정상 표시·동작을 확인한 뒤 카카오맵만 사용하도록 요청했습니다. 지도는 `KakaoMap` 하나로 렌더링하며 지도 선택 메뉴와 다른 지도·타일 렌더러, 공급자 자동 선택·전환을 제거합니다. 사용자 확인을 물리 트랙패드·모바일의 전체 검증으로 확대해 해석하지 않습니다.

- 배경지도·행정동 중심·분석 경계·시설 마커는 카카오지도 Web SDK로 표시합니다. 경계 좌표를 카카오에서 제공받는다는 뜻은 아니며, 좌표 출처와 자체 표기는 아래 [행정동 경계](#행정동-경계-데이터와-자체-표기)를 구분합니다.
- 앱 키가 없거나 SDK·타일 연결에 실패하면 `role="alert"`인 카카오맵 오류 안내를 표시합니다. ‘카카오지도 다시 시도’는 카카오맵을 다시 연결하며 외부 지도나 기본 위치도로 바꾸지 않습니다.
- 지역 검색·업종 선택·분석 상태는 지도 오류와 별도로 유지합니다. 지도 사용을 위해서는 JavaScript 앱 키와 서비스 URL 등록이 필요합니다.
- 지도 관련 환경변수는 `VITE_KAKAO_MAP_APP_KEY`만 사용하고 `config.kakaoMapAppKey`에서 읽습니다. 이전 공급자·타일 URL·출처·최대 줌 환경변수는 사용하지 않으므로 로컬·배포 설정에서도 정리합니다. 이전 구현과 판단 근거는 [작업 이력](WORKLOG.md)에 보존합니다.

2026-10-12 단일화 후 전체 81개 테스트와 포맷·린트·빌드를 확인했습니다. 최종 재시도 버튼 배치 수정 후 관련 15개 테스트·포맷·린트·빌드를 다시 확인했습니다. Safari `localhost:5173`에서 실제 카카오 도로지도·지도 선택 메뉴 제거·중심 위치의 성수2가1동 H 코드 `1120067000`·업종 드롭다운·두 버튼을 확인했습니다. 실제 BE·물리 트랙패드·모바일의 전체 검증은 별도입니다.

## 행정동 경계 데이터와 자체 표기

확인일: 2026-10-12, FE 정적 제공 대안 추가 확인 2026-10-20. 공식 공개 문서와 현재 FE 코드를 검토한 결과이며, 실제 경계 API 인증·데이터 수집·연동 검증은 수행하지 않았습니다.

**카카오 공개 API에서 행정동 경계 좌표를 받는 기능은 확인되지 않았지만, 별도로 확보한 경계를 카카오맵 위에 우리 코드로 표시하는 것은 가능합니다.** 배경지도는 카카오맵만 유지하고 경계 데이터의 출처만 별도로 둡니다.

### 카카오가 제공하는 범위

| 확인 항목                | 공개 API에서 확인한 범위                                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 좌표의 행정동 조회       | `Geocoder.coord2RegionCode` / REST `coord2regioncode`로 H/B 구분·코드·지역명·좌표 조회 가능. 경계 꼭짓점 배열은 응답 필드에 없음 |
| 행정동 경계 원본 조회    | 현재 REST·Web SDK 명세에서 행정동 코드로 경계 Polygon/GeoJSON을 반환하는 API를 확인하지 못함                                     |
| 경계선·채움 표시         | 우리가 전달한 좌표로 `kakao.maps.Polygon`을 만들고 선 색·굵기·투명도와 채움 스타일을 지정 가능                                   |
| 지역명·코드 등 자체 표기 | `CustomOverlay`에 HTML 요소와 위치를 전달해 자체 디자인·내용·클릭 동작을 구현 가능                                               |
| `MapTypeId.USE_DISTRICT` | 지적편집도 타일 오버레이. 행정동 원본 경계 좌표 조회나 개별 경계 스타일 제어 API로 취급하지 않음                                 |

근거: [현재 카카오맵 REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api), [Web SDK 명세](https://apis.map.kakao.com/web/documentation/), [다각형·지역명 표시 공식 예제](https://apis.map.kakao.com/web/sample/addPolygonMouseEvent2/). 공식 예제도 `areas[].path` 좌표를 코드에서 준비해 그리며, 경계를 자동 수신하는 예제가 아닙니다.

카카오 데브톡의 [2020-09-02 답변](https://devtalk.kakao.com/t/topic/108582)도 카카오맵 서비스에서 검색 시 보이는 지역 경계를 표시하는 별도 API는 제공하지 않는다고 안내합니다. 오래된 답변만으로 현재 상태를 단정하지 않고 위 최신 공개 명세의 응답·기능 목록을 함께 확인했습니다. 따라서 공개 API를 사용하는 현재 프로젝트에서는 **카카오 경계 원본 수신을 전제로 개발하지 않는 것**이 조사 결론입니다. 별도 제휴·기업 계약의 제공 여부는 확인하지 않았습니다.

2026-10-20 직접 수신 문의로 위 공개 REST 명세·좌표의 행정구역 응답·Polygon 공식 예제·데브톡 답변을 다시 확인했습니다. **카카오 공개 API만으로 행정동 경계 좌표를 직접 받는 방법은 확인되지 않았습니다.** `coord2RegionCode`의 H/B 코드·지역명·대표점은 경계 꼭짓점 목록이 아니며, 공식 다각형 예제도 `areas[].path`를 개발자가 준비합니다. 카카오맵 서비스 화면에서 보이는 경계와 외부 개발자에게 제공하는 API 범위를 구분합니다.

### 파일 없는 조회와 카카오 직접 수신의 차이

‘사용자가 파일을 내려받지 않기’와 ‘외부 경계 데이터 없이 FE만으로 처리하기’는 다른 조건입니다. **수동 파일 준비를 없애려면 경계 API를 사용할 수 있지만, 실제 경계 데이터는 여전히 필요합니다.**

| 방식                                           | 직접 준비할 경계 파일 | 확인할 연결 조건                                                                                                                                                     |
| ---------------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SGIS 원본 사전 가공·FE 정적 제공               | 필요                  | 아래 원본/이용 조건 준비, H10 대응·좌표 변환·버전 배포                                                                                                               |
| FE → 경계 BE/서버리스 → SGIS API → 카카오 표시 | 불필요                | API 서비스 인증·사용 조건·호출 한도, 서버의 토큰/코드 대응/CRS 처리·응답 검증. 기존 `GET /regions/{H10}/boundary` 구조를 유지할 수 있는 대안이며 현재 실제 BE는 없음 |
| FE → SGIS API 직접 조회 → 카카오 표시          | 원본 ZIP은 불필요     | 현행 브라우저 인증 경로·허용 출처/CORS·토큰 갱신/한도·사용 조건·H10 대응·CRS의 실제 검증 필요. 운영 가능한 FE 단독 방식으로 확정하지 않음                            |

[SGIS 경계 API](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/addressBoundary.html)는 GeoJSON 경계와 `accessToken`·기준연도·SGIS 행정구역코드를 사용하는 경로를 문서화합니다. [인증 명세](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/basics.html)는 `consumer_key` + `consumer_secret`으로 토큰을 발급받는 경로와, `consumer_key`만으로 JavaScript를 전달하는 `javascriptAuth.json` 경로를 구분합니다. 후자는 토큰 반환 API로 명시되어 있지 않으므로 ‘secret이 필요하니 FE는 무조건 불가능’이나 ‘JS 경로가 있으니 브라우저 경계 REST 조회가 바로 가능’으로 단정하지 않습니다. Secret을 FE의 VITE 환경변수에 넣는 방식은 사용하지 않습니다. 실인증·CORS·호출 한도·현행 JavaScript 경로 지원 여부는 미검증입니다.

따라서 파일 준비를 생략하려는 경우에는 경계 BE/서버리스를 통한 SGIS API 연계를 대안으로 검토할 수 있습니다. 지도 표시는 계속 카카오맵이며 현재 합의한 SGIS 정적 준비 방향·앱 동작·API 계약을 이번 문의만으로 변경하지 않습니다. 카카오 공개 API만으로 실제 경계를 생성하거나 합성 도형으로 대신하는 방식도 사용하지 않습니다.

### 현재 FE 표시와 계약

- [KakaoMap.tsx](../src/components/KakaoMap.tsx)는 별도 조회한 행정동 경계의 모든 Polygon/MultiPolygon·내부 구멍을 그립니다. 독립 경계 조회 대상이 없으면 기존 분석 응답의 `map.boundary` 단일 링 표시를 유지합니다. 선은 2px·`#62876c`, 채움은 `#8cac7d`이며 스타일은 우리 코드가 지정합니다.
- 같은 컴포넌트는 HTML 요소와 `CustomOverlay`로 행정동 중심 마커·시설·조회점을 표시합니다. 새 경계 라벨은 BE가 제공한 `labelPosition`에 `regionName`을 표시하며 `textContent`·표시 전용 요소를 사용합니다.
- [Dashboard.tsx](../src/pages/Dashboard.tsx)의 기존 분석 데이터와 [AreaMap.tsx](../src/components/AreaMap.tsx)의 독립 경계 조회를 분리합니다. 우클릭 H 조회 성공 또는 공식 H10 선택 시 분석 전에 경계를 요청할 수 있습니다. 실제 응답 제공은 BE 후속 작업입니다.
- [demo.ts](../src/data/demo.ts)의 경계는 중심점에 오프셋을 더한 4점 사각형으로 **실제 행정동 경계가 아닙니다.** 실제 경계 좌표가 필요하지만 제공 방식은 BE API 또는 검증된 FE 정적 파일이 될 수 있습니다. 현재 구현은 BE API 방식이며 정적 파일 방식은 아래 제안입니다.
- 기존 `Analysis.map.boundary`는 WGS84 `[위도, 경도][]`인 단일 링을 유지합니다. 새 독립 `RegionBoundary`는 GeoJSON Polygon/MultiPolygon의 `[경도, 위도]` 좌표와 출처·기준일·대표점을 받으며 모든 링을 보존해 지도 좌표로 변환합니다. 분석·저장 데이터 스키마를 바꾸지 않고 타입·검증·렌더러를 별도로 추가했습니다. [독립 경계 계약](API.md#get-regionsh10boundary)을 참조합니다.

### 경계 데이터 후보와 권장 연계

공식 기술 후보는 **SGIS 행정구역경계 GeoJSON API**입니다. [최신 주소·경계 명세](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/addressBoundary.html)는 `https://sgisapi.mods.go.kr/OpenAPI3/boundary/hadmarea.geojson`과 `accessToken`, `year`, `adm_cd`, `low_search`를 안내합니다. 특정 읍면동은 해당 코드와 `low_search=0`으로 조회합니다. 확인 시 문서의 읍면동 코드는 **8자리**, 기준연도 범위는 **2000~2025**입니다. 과거 7자리 안내나 카카오 H10과 혼용하지 않습니다.

운영 채택은 미확정이며 다음 확인이 필요합니다.

- **코드·기준일:** 카카오 H10과 SGIS 통계 코드는 별도 체계입니다. [지역코드 기준](REGION_CODES.md)에 따라 출처·기준일에 맞는 대응 관계를 API 방식에서는 BE가, 정적 방식에서는 데이터 가공·갱신 담당자가 관리합니다. H10을 단순 절삭하거나 이름만으로 매칭하지 않습니다. 최신 경계와 과거 분석 통계의 분동·통합 차이도 확인합니다.
- **좌표계:** [SGIS 다운로드 자료 기준](https://link.mods.go.kr/view/pss/downloadList)은 경계자료의 EPSG:5179와 기준년도 6월 30일을 안내합니다. 이번에 확인한 API 경계 섹션에는 CRS가 명시되지 않아 API 실응답의 CRS는 추가 확인 대상입니다. 확인 후 WGS84로 실제 좌표 변환하며 CRS 이름만 바꾸지 않습니다. GeoJSON을 도입할 경우 좌표 순서와 현재 앱의 `[위도, 경도]` 형식 차이도 어댑터에서 처리합니다.
- **인증·사용 조건:** [SGIS 인증 명세](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/basics.html)의 서비스 Secret은 BE에서 관리합니다. 공개 [API 약관](https://sgis.mods.go.kr/developer/html/openApi/app/rules.html)에는 사전 승낙 없는 영업활동 제한이 있으나 시행일이 2015년인 화면이므로 현재 신규 계약·상용 승인·출처 표시·캐시·재배포 조건을 제공기관에 확인해야 합니다. 무상 API라는 이유로 운영 사용이 승인됐다고 간주하지 않습니다.

연계 흐름은 다음과 같습니다. **FE 조회·표시는 구현했지만 BE API·실제 데이터 확보·팀 계약 확정은 미완료**입니다.

1. FE가 현재처럼 카카오 좌표 조회에서 원본 10자리 H 코드와 지역명을 받습니다.
2. BE가 사용 조건을 확인한 공식 경계 데이터와 H 코드 대응표를 준비하고, 출처·경계 기준일·원본 CRS를 관리합니다.
3. BE가 새 `GET /regions/{regionCode}/boundary`의 독립 경계 응답을 제공합니다. 기존 `POST /analyses`의 단일 링 계약도 유지하며 새 응답 구조·코드 매핑·사용 조건은 BE/FE가 검토합니다.
4. FE는 카카오맵의 `Polygon`과 `CustomOverlay`로 선·채움·지역명을 직접 표시합니다. 경계가 없으면 중심점을 사용하고 합성 사각형을 실제 경계처럼 표시하지 않습니다.

사용자가 2026-10-12 구현을 승인하고 BE API가 아직 없으므로 FE를 먼저 구현해 인계하도록 확인했습니다. FE 동작은 아래에, BE의 실제 경계 수집·endpoint·운영 연결 작업은 [인계 문서의 BE-09](BACKEND_HANDOFF.md#2-백엔드-작업-목록과-완료-조건)에 정리합니다.

### 독립 경계 조회·표시

- 원본 10자리 H 코드를 `GET /regions/{regionCode}/boundary`에 전달합니다. 우클릭 카드의 H 코드가 선택 지역보다 우선하며, 카드가 없으면 선택 H10을 조회합니다. 8자리 카탈로그 코드를 임의로 늘리거나 FE 목록으로 조회를 차단하지 않습니다.
- 조회 응답은 [전용 검증·어댑터](../src/lib/regionBoundary.ts)를 통과해야 합니다. 원본 요청 코드 일치, `regionType: H`, `EPSG:4326`, 유효 경위도·닫힌 링·최소 3개 서로 다른 점·출처·실제 날짜를 확인합니다. 링의 위상·행정동 일치·대표점의 경계 내부 여부는 BE가 검증해야 합니다.
- [조회 훅](../src/lib/useRegionBoundary.ts)은 H 코드와 재시도 세대별로 로딩·성공·없음·오류를 구분합니다. 새 위치 조회·카드 닫기·선택 지역/표시 지역 목록 변경·둘러보기·언마운트 시 이전 요청을 취소하고 늦은 응답을 무시합니다. 업종만 바꾸면 같은 지역 경계를 유지합니다. 카드 닫기 후 선택 H10으로 돌아오면 다시 조회하며 별도 경계 캐시는 아직 없습니다.
- 성공 시 모든 폴리곤·구멍과 자체 지역명 라벨을 표시하고 카드 또는 지도 안내에 출처 링크·경계 기준일을 제공합니다. 라벨은 지도 입력을 가로채지 않으며 독립 경계 응답만으로 지도 중심·확대 배율을 바꾸지 않습니다. 공개 중첩 `path`는 [카카오 구멍 예제](https://apis.map.kakao.com/web/sample/donut/)를 따릅니다.
- 조회 중·없음·오류·경계 그리기 실패에서는 해당 독립 경계를 숨깁니다. 경계 상태와 ‘경계 다시 조회’를 지도 연결 오류와 분리하며 분석·둘러보기를 계속 사용할 수 있습니다. 독립 조회 대상을 다른 지역의 이전 분석 경계나 데모 사각형으로 대신 표시하지 않습니다. 독립 조회 대상이 없는 기존 분석 경로에만 단일 링 표시를 유지합니다.
- 둘러보기는 경계를 숨기고 클릭 위치를 확대합니다. 분석 버튼의 `POST /analyses` 계약은 그대로이며 경계 조회 실패가 분석 지원 여부나 표본 부족 판정을 대신하지 않습니다.
- 기본 데모에서는 경계 HTTP 요청을 보내거나 실제 경계를 합성하지 않고 ‘데모에서는 실제 행정동 경계를 제공하지 않아요’라고 안내합니다. 실제 API 모드의 `404 + BOUNDARY_NOT_AVAILABLE`만 경계 없음으로 처리하며 endpoint 누락의 일반 404·HTML/204·잘못된 CRS/코드·서버 장애는 오류로 구분합니다.

구현은 [이슈 #7](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/7)에서 기존 지도 작업 #1의 하위 범위로 관리하며 `feature/1-map-workspace`·Draft PR #3에 포함합니다. 모의 API/SDK 검증과 실제 경계 서비스 연결은 구분하며 실행 결과·시각 검증 제한은 [작업 이력](WORKLOG.md)에 기록합니다.

### FE 정적 경계 제공 대안

2026-10-20 사용자 요청에 따라 조사했습니다. **경계 표시는 BE 없이 FE 정적 호스팅으로 해결할 수 있습니다.** 공식 경계를 미리 확보·검증·변환해 배포하면 실행 중에는 정적 파일만 읽어 기존 카카오 렌더러에 전달하면 됩니다. 위의 ‘BE가 제공’은 현재 선택한 연결 방식이며 기술적 필수 조건이 아닙니다. 이 절은 [이슈 #10](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/10)의 조사·제안이며, 데이터 파일·로더·데모 표시 변경은 아직 구현하지 않았습니다.

#### SGIS 자료 준비와 역할 분담

2026-10-20 사용자 준비 사항을 정리합니다. 현재 필요한 것은 **회원 신청으로 받은 전국 읍면동 경계 원본 ZIP과, 신청/다운로드 화면에만 나타나는 해당 자료의 이용 조건**입니다. 공개 코드표·설명서 조사와 데이터 가공을 사용자에게 넘기지 않습니다.

1. 사용자가 [SGIS 자료제공 절차](https://sgis.mods.go.kr/view/pss/dataProvdIntrcn)에 따라 본인 계정으로 로그인하고 자료를 신청합니다. 신청 대상은 **센서스용 행정구역경계 · 읍면동 · 전국 · SHP · 같은 자료연도**입니다. 확인 시 공식 목록의 최신 연도는 2025년이므로 우선 2025년 자료를 준비합니다. 실제 신청 화면의 전국 선택/파일 분할 방식은 미확인이고, 시도별로 받게 되면 서울을 포함한 모든 시도의 연도를 맞춥니다.
2. 다운로드한 ZIP을 가공하지 않은 상태로 전달하거나 저장소 밖의 로컬 파일 경로를 알려줍니다. SHP는 도형 하나만으로 완결된 자료가 아니므로 `.shp`·`.shx`·`.dbf`·`.prj` 및 동봉된 인코딩 파일·코드표·README 등 전체를 보존합니다. 대용량 원본은 Git에 커밋하지 않습니다. 실제 압축 구성·CRS·코드 필드·누락 여부는 자료를 받은 뒤 확인합니다.
3. 신청/다운로드 화면이나 동봉 문서에 있는 해당 자료의 이용 조건·공공누리 표시·출처 문구·별도 승인 조건을 함께 보관합니다. 공개되지 않은 조건이 있으면 그 내용이나 안내 링크를 전달합니다. 일반 정책의 존재만으로 특정 파일의 정적 재배포 조건을 확인했다고 처리하지 않습니다.

FE/데이터 작업에서는 공개 코드표·이용설명서를 확보하고, 원본 코드/H10 대응·기준일·사용 조건을 대조한 뒤 실제 CRS 변환·도형/대표점 검증·GeoJSON 분할·manifest·정적 로더·카카오 표시를 구현합니다. 사용자가 QGIS 설치·좌표 변환·JSON 가공·H 코드 대응표 작성을 먼저 할 필요는 없습니다. 선택한 사전 다운로드/정적 방식에는 SGIS API 키 발급이 필요하지 않으며 현재 카카오 JavaScript 키 설정은 유지합니다. 현재 계정 조작·약관 동의·자료신청·파일 수령·사용 조건 확인·정적 연결은 수행하지 않았습니다.

#### 권장 처리 흐름과 변경 범위

1. 배포 전에 공식 원본의 사용 조건·경계 기준일·코드 체계를 기록하고, [지역코드 기준](REGION_CODES.md)에 맞는 원본 코드↔카카오 H10 대응을 검증합니다. 코드를 임의 절삭하거나 이름·접미사 `00`만으로 연결하지 않습니다.
2. 원본을 오프라인에서 WGS84 GeoJSON `[경도, 위도]`로 실제 변환합니다. 모든 폴리곤·구멍·섬을 보존하고 링 폐합·위상·실제 행정동 일치·경계 내부 대표점을 검사합니다. 출처·라이선스·원본/가공 버전·변환 도구·기준일을 함께 관리합니다.
3. 기존 `RegionBoundary` 형태로 H10별 파일과 지원 코드/파일 목록인 manifest를 생성합니다. 경로 예시는 `public/boundaries/{데이터버전}/{H10}.json`이며 **아직 존재하는 경로가 아닙니다.** [Vite 정적 자산 규칙](https://vite.dev/guide/assets#the-public-directory)에 따라 `public/` 파일은 빌드 결과에 복사됩니다. 대용량 원본은 Git에 넣지 않고 재현 가능한 가공 절차·검증 결과를 관리하며, 배포 파일의 실제 크기·전송량을 측정합니다.
4. 우클릭으로 조회한 원본 H10의 파일만 필요할 때 읽고 현재 검증·좌표 어댑터·`Polygon`/`CustomOverlay`를 재사용합니다. 전국 도형을 초기 JS 번들에 넣거나 전부 그리지 않습니다. 같은 출처의 정적 배포를 우선하며, 별도 CDN이면 CORS를 따로 확인합니다. 경계용 외부 API 키 없이 제공할 수 있지만 배경지도와 좌표의 행정동 조회는 계속 카카오를 사용합니다.
5. 현재 `requestJson`은 `apiBaseUrl`을 붙이므로 정적 URL 로더를 분리해야 합니다. 취소·30초 제한·늦은 응답 무시·재시도·응답 H10 일치 검사를 유지합니다. manifest에 없는 코드는 미제공으로 안내하고, 목록에 있는 파일의 404·SPA HTML·잘못된 JSON·버전 불일치는 오류로 처리합니다. 기존 API의 `404 + BOUNDARY_NOT_AVAILABLE` 규칙은 변경하지 않습니다.
6. 경계 소스와 분석 데모 모드를 분리합니다. 현재 `getRegionBoundary`는 데모에서 `null`을 반환하고 `AreaMap`은 실제 경계 미제공으로 안내합니다. `demoMode=false`로 우회하면 카탈로그·분석까지 BE를 호출하므로 사용하지 않습니다. 실제 정적 경계를 연결하면 ‘분석은 데모, 경계는 공식 공개자료’로 구분하고 지도·가이드·소개 안내도 함께 바꿉니다. 8자리 데모 목록 선택은 별도의 검증된 H10 대응이 필요하며 알려진 코드 불일치를 그대로 확장하지 않습니다.
7. 파일명/디렉터리 버전과 manifest를 함께 배포하고 캐시를 관리합니다. 행정동 분동·통합 때 다시 가공·검증·배포합니다. 표시 경계 기준일과 분석 통계 기준 시점의 차이를 보존하며 오래된 경계를 최신 행정동으로 간주하지 않습니다. 필요 시 이후 BE/CDN 제공으로 옮길 수 있지만 자동 전환은 이번 제안에 포함하지 않습니다.

정적 제공을 적용하면 **경계 표시용 BE endpoint를 기다릴 필요가 없어집니다.** 분석 API·통계/AI·지원 지역/데이터 부족 판단의 BE 역할은 그대로입니다. 현재 앱은 아직 BE 경계 API 방식이고 기본 데모에는 실제 경계가 없습니다. 원본 다운로드·H10/경계 기준일 대조·변환·정적 로더·전송량/실지도 검증·운영 배포는 후속 구현 사항입니다.

[Kakao 지도 Web API 가이드](https://apis.map.kakao.com/web/guide/)에 따라 앱을 준비하고 개발/운영 서비스 URL을 등록합니다. 브라우저용 JavaScript 키를 사용하며 REST API 키나 관리자 키를 넣지 않습니다. VITE 환경변수는 번들에 노출되므로 허용 도메인 제한을 설정합니다. 계정 생성·약관 동의·앱 키 발급은 이 작업에서 수행하지 않았습니다.

### 연결 오류 확인 순서

1. `.env` 또는 `.env.local`의 `VITE_KAKAO_MAP_APP_KEY`가 해당 앱의 **JavaScript 키**인지 확인합니다. 실제 키는 로그·문서·이슈에 남기지 않습니다.
2. 해당 JavaScript 키의 허용 도메인에 현재 브라우저의 출처를 등록합니다. 로컬 개발의 `http://localhost:5173`과 `http://127.0.0.1:5173`은 서로 다른 출처입니다. 포트나 프로토콜이 달라지면 해당 주소도 확인합니다.
3. 앱의 카카오맵 사용 설정을 확인합니다. 설정 경로와 조건은 [카카오맵 공식 안내](https://developers.kakao.com/docs/ko/kakaomap/common)를 기준으로 확인합니다.
4. 환경변수 변경 후 개발 서버에 새 값이 반영됐는지 확인하고 브라우저를 새로고침합니다. 배포 환경은 다시 빌드합니다.
5. 브라우저 네트워크에서 SDK 응답, 지도 이미지 로딩, 실제 지도 표시를 각각 확인합니다. SDK HTTP 200만으로 지도 표시 완료를 판단하지 않습니다.

| 실제 응답                              | 의미 및 조치                                                                 |
| -------------------------------------- | ---------------------------------------------------------------------------- |
| HTTP 401, `appKeyType is REST_API_KEY` | Web SDK에 REST API 키를 전달한 상태. JavaScript 키로 교체                    |
| HTTP 401, `domain mismatched!`         | 현재 출처가 해당 키의 허용 도메인과 불일치. 현재 프로토콜·호스트·포트를 등록 |
| SDK 성공 후 배경 지도 실패             | 타일 요청·앱 사용 설정·브라우저 오류를 별도로 확인                           |

2026-10-08 로컬 점검에서 REST API 키 오류와 키 교체 후 허용 도메인 불일치를 순서대로 확인했습니다. 후속 제스처 작업 시 두 로컬 출처의 SDK 응답이 HTTP 200으로 바뀌었고, Chrome의 `localhost:5173`에서 실제 카카오 도로지도 표시와 우클릭·중심 위치의 서교동 행정동 조회 성공을 확인했습니다. 키 값은 기록하지 않았으며 `.env`는 Git 제외 대상임을 확인했습니다. `127.0.0.1:5173`의 실제 렌더링·운영 도메인 연결은 별도로 확인해야 합니다.

### 카카오 지도 조작

화면을 채우는 지도를 바로 탐색하도록 SDK 생성 옵션에 `draggable: true`, `scrollwheel: true`, `disableDoubleClick: false`, `disableDoubleClickZoom: false`를 적용합니다. 드래그·더블클릭·모바일 터치는 SDK 기본 동작을 사용합니다. `scrollwheel`은 SDK의 터치 확대·축소도 제어하므로 활성화 상태를 유지합니다.

사용자가 트랙패드 스크롤이 페이지 입력으로 처리된다고 보고해 `src/lib/kakaoMapWheel.ts`에서 카카오 지도 컨테이너에만 네이티브 `wheel` 리스너를 추가했습니다. `{ capture: true, passive: false }`로 기본 스크롤을 취소하고 SDK 내부로 같은 이벤트가 전달되지 않게 합니다. 공개 API `getProjection().coordsFromContainerPoint()`와 `setLevel(level, { anchor, animate })`로 포인터 위치를 기준으로 확대·축소하며 SDK 비공개 함수를 호출하지 않습니다.

- 픽셀·줄·페이지 단위를 환산하고 작은 세로 입력도 누적합니다. 누적 40px에 한 단계씩 200ms 애니메이션으로 전환합니다. `zoom_start`·`zoom_changed`로 실제 전환 완료를 기다리며, 완료 뒤 다음 프레임에서 예약된 입력을 처리합니다. 동작 줄이기 설정에서는 애니메이션을 생략합니다.
- 전환 중에는 다음 한 단계까지만 입력을 보관해 관성 입력이 긴 대기열로 쌓이지 않게 합니다. 다음 확대 직전에 현재 지도와 최신 포인터 좌표로 기준 위치를 다시 계산합니다. 방향 전환·180ms 초과 입력 중단 시 누적값을 초기화하며, 완료 시점에도 마지막 입력이 180ms보다 오래되었으면 실행하지 않습니다.
- 도로지도 배율 1~14에서 제한합니다. 배율 끝과 수평 위주 입력에서도 페이지 스크롤은 취소하되 수평 입력으로 확대하지 않습니다. 지도 안의 Ctrl+휠도 지도 입력으로 처리합니다.
- 검색 오버레이·결과 패널·조회 카드는 지도 컨테이너의 형제 요소이므로 이 리스너의 대상이 아닙니다. 그 안의 목록 스크롤은 유지합니다. 지도 안의 행정동·시설 마커 위 휠은 지도 확대·축소로 처리하고 버튼 클릭은 그대로 유지합니다.
- 지도 이탈·포인터 누름·터치 시작 시 예약 입력을 취소합니다. 언마운트 시 네이티브/SDK 리스너와 다음 프레임 예약을 모두 제거합니다. 더블클릭·우클릭·터치 자체의 동작은 SDK와 기존 조회 기능이 처리합니다.

공식 배포 SDK `4.5.28`에서 `wheelDelta` 없는 1px 미만 `deltaY` 입력을 누적하지 않는 경로를 확인했습니다. 사용자 환경의 원시 이벤트를 수집하지 않아 해당 분기가 현장 문제의 단일 원인인지는 확정하지 않았습니다. SDK 옵션만 재설정하는 대신 표준 `wheel` 입력과 스크롤 취소를 직접 처리합니다.

| 입력                               | 동작                    | 2026-10-09 기준 확인 상태                                                |
| ---------------------------------- | ----------------------- | ------------------------------------------------------------------------ |
| 왼쪽 버튼 드래그                   | 지도 이동               | 사용자 정상 동작 확인                                                    |
| 마우스 휠·트랙패드 세로 스크롤     | 지도 확대·축소          | 모의 테스트·Chrome 자동 양방향 확대 확인, 물리 트랙패드 체감 재확인 대기 |
| 더블클릭                           | 클릭 지점 확대          | 사용자 정상 동작 확인                                                    |
| 오른쪽 버튼 클릭                   | 클릭 좌표의 행정동 조회 | 실제 서교동 H 코드 `1144066000` 조회 성공                                |
| 한 손가락 이동·두 손가락 확대/축소 | SDK 터치 탐색           | 설정 적용, 실제 모바일 기기 미검증                                       |

확대·축소 버튼과 ‘중심 위치 조회’도 유지합니다. 조작 안내는 이용 가이드에 제공합니다.

이전 자동 조작에서 축척 `100m` → `250m` 변화만 확인한 기록은 실제 트랙패드 입력과 페이지 스크롤 차단의 검증으로 충분하지 않았습니다. 사용자 보고에 따라 휠 정상 동작 판정을 철회했습니다. 2026-10-08 보정 직후 브라우저 자동 검증은 두 차례 `Sky Computer Use native pipe startup failed`로 연결되지 않았습니다. 2026-10-09에는 연결을 복구해 아래 자동 확인을 수행했으나 물리 트랙패드 검증과는 구분합니다.

#### 확대·축소 끊김 점검

2026-10-09 사용자가 지도 확대·축소가 끊기거나 튄다고 확인했습니다. 이전 보정 코드에는 `setLevel`의 `animate` 옵션이 없어 배율이 즉시 바뀌었고, 마지막 확대 후 160ms 동안 입력과 누적값을 버렸습니다. 공식 배포 SDK 4.5.28의 기본 휠은 300ms 애니메이션을 사용하므로 보정 경로에서 전환 방식이 달라졌습니다. 사용자 원시 입력을 수집하지는 않았지만, 즉시 전환과 입력 유실은 코드와 회귀 테스트에서 확인한 원인입니다.

공개 `setLevel` 애니메이션을 200ms로 적용하고 고정 시간 동안 입력을 버리는 처리를 제거했습니다. SDK가 애니메이션 중 다음 `setLevel` 호출을 무시할 수 있어 고정 타이머 대신 공개 확대 이벤트로 완료를 기다립니다. 입력 보관·취소 기준은 위와 같으며 배율은 SDK의 정수 단계 단위로 바뀝니다.

- 모의 SDK에 전환 중 호출 무시·완료 지연을 반영했습니다. 수정 전 관련 파일에서 7개 실패·17개 통과를 확인했고, 수정 후 24개 모두 통과했습니다. 작은 입력 연결·실제 완료 지연·방향 전환·최신 포인터·관성 제한·중단/언마운트 취소·동작 줄이기를 포함합니다. 전체 11개 파일·72개 테스트, 포맷·린트·빌드가 통과했습니다.
- Chrome의 `localhost:5173`을 새로고침한 뒤 실제 카카오 도로지도에서 네이티브 자동 스크롤로 축척 `250m` → `100m` → `250m`과 화면 상단 유지 상태를 확인했습니다. 작은 자동 입력에는 배율이 바뀌지 않았습니다. 이는 양방향 입력 처리 확인이며 실제 트랙패드의 원시 이벤트 재생이나 프레임 측정은 아닙니다.
- 물리 트랙패드에서 부드러움·감도·포인터 기준 위치, 마커 위 휠, 패널 내부 스크롤을 다시 확인해야 합니다. 이전 축척 변화만으로 정상 체감을 확정했던 판정을 되살리지 않습니다.

수동 확인은 지도 빈 영역에서 두 손가락 세로 스크롤 양방향의 축척 변화·포인터 기준 위치 유지·페이지 고정, 지도 마커 위 휠, 검색 목록·결과 패널 내부 스크롤을 구분해 진행합니다. 드래그·더블클릭·우클릭·모바일 터치도 수정 후 회귀 확인 대상입니다. 미세 이동 후 타임아웃 오탐 수정은 별도 PR #4로 `develop`에 병합되었으며 2026-10-12 최신 `develop` 병합으로 이 feature 브랜치에도 포함했습니다.

### 지도 위치의 행정동 조회와 분석·둘러보기

행정동 H/법정동 B 구분, 코드 출처·자릿수, 데모 전용 매칭과 공식 확인 절차는 [지역코드 기준](REGION_CODES.md)을 따릅니다.

2026-10-09 사용자 사양 변경에 따라 기존 ‘이 지역 선택’과 FE 지역 목록 포함 여부 검사를 제거했습니다. [이슈 #1](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/1)의 기존 지도 탐색 목적을 보완하며 `feature/1-map-workspace`·Draft PR #3에서 진행합니다.

- 카카오 `rightclick`에서 실제 위경도를 받아 공식 `services.Geocoder.coord2RegionCode`에 **경도, 위도** 순서로 전달합니다. SDK는 `libraries=services`를 로드합니다. 행정동(`region_type: H`)의 유효한 10자리 코드와 이름을 사용하며 법정동·가장 가까운 마커로 대체하지 않습니다.
- 조회 카드에는 행정동 이름·코드·좌표, ‘분석할 업종’ 드롭다운, ‘이 지역 분석’·‘이 지역 둘러보기’를 표시합니다. 업종은 현재 검색 조건과 동기화하고 대분류별 옵션 그룹으로 표시합니다. 사용자 표현의 ‘데이터’는 현재 분석 계약에 맞춰 업종으로 해석했습니다. 지표 선택을 뜻하는지는 추가 답변 전이며 [API 초안](API.md)에 구분했습니다.
- **이 지역 분석**: FE 지역 카탈로그에 없는 행정동도 조회한 10자리 H 코드와 선택 업종을 기존 `POST /analyses`로 요청합니다. 기존 ‘상권 분석하기’와 `useAnalysis.run`·로딩·오류·데이터 부족·재시도·결과 패널을 공유합니다. 코드·이름·클릭 좌표는 현재 선택 상태로 유지하며 지역 목록에 삽입하거나 별도의 지역 허용 목록으로 저장하지 않습니다. 상단 재분석과 분석 저장 후 재열기에도 원본 요청 코드를 보존합니다.
- 업종 미선택·목록 조회 실패·분석 진행 중에는 새 분석을 막습니다. 분석 지원 여부·표본 부족 여부는 실제 API 모드에서 서버 응답으로 처리하며 오류를 데모 결과로 대체하지 않습니다. 실제 BE의 10자리 H 코드 수용·전국 데이터 가용성은 미검증입니다.
- **이 지역 둘러보기**: 분석 API를 호출하거나 분석 조건의 지역을 바꾸지 않습니다. 클릭 좌표로 이동해 현재 레벨과 3 중 더 확대된 배율을 사용합니다. 조회 카드·결과 패널을 접고 둘러보는 지역명을 지도에 표시합니다. 이전 분석의 경계·시설 마커는 숨깁니다. 업종만 바꿀 때는 둘러보는 위치·배율을 유지하고 지역 변경·분석 실행 시 탐색 상태를 해제합니다.
- 점포명은 확대된 **카카오 배경지도 자체의 POI 표시**를 사용합니다. 점포 검색 API·전체 점포 목록·실시간 영업 현황을 제공하는 구현은 아닙니다.
- 데모 모드에서는 유일하게 일치하는 예시 지역의 8자리/10자리 코드만 대응해 예시 결과를 만들고 요청 코드는 보존합니다. 예시가 없으면 ‘데모 분석 데이터가 없습니다’라는 데이터 부족 상태를 표시하며 다른 지역 결과를 대신 보여주지 않습니다. 실제 조회 행정동을 분석하는 API 모드는 FE 예시 목록과 무관합니다.
- 알려진 데모 코드 불일치: 연남동은 [이슈 #5](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/5), 성수2가1동은 [이슈 #6](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/6)에서 별도로 검증합니다. 이번 UI 변경에서는 코드 데이터를 교정하거나 이름으로 우회하지 않았습니다.
- 모바일·키보드에는 ‘중심 위치 조회’ 버튼을 제공합니다. 배경지도와 행정구역 조회는 같은 카카오 SDK 로더를 사용합니다.
- 미설정·오류·빈 결과·서비스 누락·10초 무응답을 안내합니다. 다음 위치 조회·닫기·언마운트 시 이전 요청을 취소하고 늦은 응답을 무시합니다. 공유 SDK 로더 자체는 취소하지 않습니다. 지역 검색과 수동 조건 선택은 계속 사용할 수 있습니다.

검증: 2026-10-09 전체 11개 파일·58개 테스트에서 목록 밖 행정동의 POST 본문·업종 동기화·재분석·저장/재열기·오류/재시도·데이터 부족·둘러보기 무호출·뷰포트 확대·데모 제한·기존 휠 동작을 모의 검증했습니다. Chrome `localhost:5173`에서 실제 카카오 우클릭 응답·업종 드롭다운·두 버튼 배치, 둘러보기 축척 `250m` → `50m`와 점포명 표시, 미용실 선택의 상단 동기화 및 예시 없는 지역의 데모 데이터 부족 안내를 확인했습니다. 실제 BE 연결·모바일 시각 검증·수정 후 실제 트랙패드 검증은 별도입니다.

근거: [카카오 지도 공개 API 문서](https://apis.map.kakao.com/web/documentation/), [행정동 조회 예제](https://apis.map.kakao.com/web/sample/coord2addr/). 확인일은 2026-10-09입니다.

## 장애 대응

- JavaScript 앱 키 미설정, SDK 로드 실패/10초 초과, 지도 생성 실패, 첫 타일 로드 12초 초과와 반복 이미지 오류에 카카오맵 오류 안내를 표시합니다.
- 정상 로드 후 `bounds_changed`만으로 타이머를 다시 시작하지 않습니다. 타일 추가 로드 없는 미세 이동에서는 `tilesloaded`가 발생하지 않기 때문입니다. 이후 타일의 무응답 자체에는 별도 시간 제한을 적용하지 않으며 반복 이미지 오류는 계속 감지합니다.
- ‘카카오지도 다시 시도’는 현재 설정으로 카카오 SDK·지도를 재시도합니다. 버튼은 지도 컨테이너 밖의 오른쪽 하단에 두고 결과 패널보다 위에 표시해, 좁은 화면에서도 패널을 닫지 않고 재시도할 수 있습니다. 다른 지도·기본 위치도 선택이나 자동 전환은 제공하지 않습니다.
- 재시도 중에도 선택 지역·업종과 분석 요청 상태를 유지합니다. 지역 검색과 분석 폼은 계속 사용할 수 있습니다.
- 앱 키·허용 도메인·사용 설정 문제는 위 연결 오류 확인 순서대로 수정한 뒤 재시도합니다.

2026-10-08 이벤트 모의 테스트에서 정상 `tilesloaded` 이후 타일 추가 로드 없는 `bounds_changed`에도 12초 뒤 실패하는 기존 카카오 타임아웃 오탐을 재현했습니다. [이슈 #2](https://github.com/teojabi-groundbreakers/pickplace-frontend/issues/2)로 분리해 `fix/2-kakao-tile-timeout`의 별도 worktree에서 수정·검증하고 [PR #4](https://github.com/teojabi-groundbreakers/pickplace-frontend/pull/4)로 진행했습니다. 수정 당시 전체 테스트 33개·포맷·린트·빌드가 통과했으며 PR #4는 이후 `develop`에 병합되었습니다. 2026-10-12 최신 `develop` 병합으로 이 feature 브랜치에도 해당 수정이 포함되었습니다. 이번 카카오 단일화에서 새로 해결한 문제와 구분합니다.
